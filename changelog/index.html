Changelog/Releases

Changelog

Latest changes lists the changes merged into main since the last release.

2026.10.6 (2026-10-27)source

For userssource

  • Added: Signing in links the Steam accounts connected to your Discord account. Discord asks once for permission to share your connections with SLM.

    A Steam account disconnected from Discord is unlinked from SLM at your next sign-in. A Steam account already linked to someone else's account stays linked to theirs.

  • Added: Squads show their kills, wounds, deaths and K/D in the teams panel and in a past match's teams view.

    The K/W/D sort in the teams panel sorts players, or squads by their players' combined score, by kills, wounds, deaths, K/D or W/D. A squad's score shows on its header row while spoilers are shown. A past match's teams view has the same sort options, sorts by name or time on team as well, and has a search box that filters its players. Its Counted only checkbox hides the players the team breakdown does not count.

2026.10.5 (2026-10-27)source

For userssource

  • Fixed: A vote can be saved without a false Filter Warnings alert. The alert called the vote's default choice "not in the pool" even when the choice was in it, so the vote could only be saved with Save Anyway. When a vote is the next layer, the in-game next layer message to admins now lists the repeat rules and pool filters that the vote's current choice breaks.

    In Gen Vote, clicking the placement option that is already selected keeps it selected. Clicking it used to select the other option.

  • Fixed: SLM no longer misses a next layer set in the seconds after a match starts.

    An admin could set a next layer while the new match was loading, or while SLM was reconnecting to the server. SLM then neither added that layer to the queue nor overrode it. SLM now handles that change like any other.

    When the connection to the server dropped as SLM was setting the next layer, the server kept its old next layer. SLM now sets the first item in the queue once the connection is back.

    The match history showed (???) as the length of a match that lasted under a minute. It now shows 1m.

  • Fixed: The next layer no longer drifts off the queue after an admin changes it from outside SLM.

    With Override the next layer when it is set outside SLM on, SLM sometimes let an outside change stand. After a match that was not the first item in the queue, SLM also left the server's own rotation to pick the following layer. SLM now sets the first item in the queue as the next layer in both cases.

  • Fixed: The pool settings on the dashboard save every filter change. Changing whether a filter in Warn For, Constrain Generation or Layer Request Filters applies as regular or inverted no longer fails with an error.

  • Fixed: Votes start on their own again. When the next item in the queue is a vote, SLM starts it once the match reaches the Auto Start Vote Delay, and leaves it to an admin after the Auto Start Vote Cutoff.

Smaller fixes and tweaks
  • Changed: End Match works on an empty server. Squad now changes the layer when nobody is connected.
  • Changed: Training layer names show the map without the faction pair, such as "JensensRange - WPMC Combined vs TLF Combined".

For operatorssource

Smaller fixes and tweaks
  • Fixed: The Docker image runs Node.js 24.22.1, which includes the Node.js security releases of July 28 and October 20, 2026.

2026.10.4 (2026-10-21)source

For userssource

  • Added: Layer tables summarize the layers that match your filters.

    Each column with a fixed set of values, such as Map or Unit, shows in its header how many different values the matching layers hold. Hover over the header to see those values and how many layers hold each one. Hover over a score column's header to see the lowest and highest score among the matching layers.

    Switch to Summary beside the matched layers count to see every column's values at once, the score ranges, and how many layers each filter matches or removes.

  • Changed: Presence lists show one avatar per user. Another of your tabs or devices appears separately only while it is editing.

    The warning about your other sessions appears only when one of those sessions is editing. Its button, now Stop editing there, ends their editing sessions. The warning also says when stopping them discards unsaved edits, which happens when no one else is editing the same thing.

  • Changed: Dragging a queue item or a layer request is easier to aim. Drop it anywhere between the middles of two items to move it there, or on the area at the end of another item to make a vote from the two queue items, or to combine the two requests.

    Dropping on a layer's name no longer creates a vote, and dropping on a request's description no longer combines requests. The Create Vote and Combine areas appear while an item is dragged. To move an item to the top of its list, release it anywhere between the list's header and the middle of the first item. A dragged queue item is shown faded rather than as an empty box.

  • Changed: SuperMod layers match SuperMod's current release. The Belaya, Chornivsk, Hrodna Border and Rassvet maps are added, and the Johat, Khokhan, Mogadishu and OP First Light layers that SuperMod no longer ships are removed.

    Each SuperMod layer takes its map and gamemode from SuperMod's own data, which is what the game loads. A GoingDark or Large variant shares its map with the layer it is built on: SU_GoingDark_Tallil_RAAS_v1 is on Tallil, and SU_Chora_LargeInvasion_v1 on Chora. SU_Tallil_SeedVehicle_v1 is a Seed layer, SU_GoingDark_Narva_RAAS_v1 a RAAS PreCap layer, and SU_GoingDark_Narva_RVAAS_v1 a RAAS layer.

    GoingDark layers, SuperMod's night layers, carry a GD version, such as V1GD for SU_GoingDark_Narva_RAAS_v1, the way a world-partitioned layer carries WP. A filter on the version can include or exclude them.

    Some vehicles that only SuperMod ships are renamed to the names SuperMod now gives them, such as Mi8 CAS for Mi-8 CAS. A filter on a vehicle's old name no longer matches it, so check vehicle filters for SuperMod vehicles.

    Vehicles that vanilla Squad also ships take their class from vanilla Squad. The BRDM-2 is a light vehicle and the Technical BMP-1 a tank destroyer again, and the CH-146 CAS is an attack helicopter.

  • Removed: Resurgence and Galactic Contention layers are no longer in the layer catalog, because neither mod has been updated for Squad v10.6. They return once each mod is updated.

    A queue item on one of their layers stays in the queue, marked as an unknown layer. A server whose Installed Mods names either mod lists it as not in the catalog.

  • Fixed: The layer table no longer fails with "Error loading layers" after the server moves to new layer data.

  • Fixed: SLM no longer signs you out a week after you sign in while you are still using it. SLM now signs you out only after 6 days without a visit, and an open tab counts as a visit.

  • Fixed: The vehicle tables in layer details show each vehicle's ticket value. Since 2026.10.2 the column showed a dash for every vehicle.

Smaller fixes and tweaks

  • Fixed: SLM no longer fails to read players and squads from the game server while it warns many players at once, such as everyone on a full server.

    An RCON command no longer times out while it waits behind other commands, and no longer receives the reply to a different command.

For operatorssource

Smaller fixes and tweaks
  • Fixed: The published Docker image carries its org.opencontainers.image.source and org.opencontainers.image.description labels again. A docker image prune filtered on the source label removes old SLM images again.

2026.10.3 (2026-10-21)source

For userssource

  • Fixed: The About page opens again, instead of showing "This page failed".
Smaller fixes and tweaks

  • Fixed: The All Permissions table fits inside the Permissions dialog. Long descriptions, scopes and role names wrap instead of pushing the Scope and Granted By columns out of view.

    Roles granted through a filter's role contributors no longer show "undefined" after the filter name.

  • Fixed: A player who leaves the server no longer reappears in the teams panel for a few seconds afterwards. Counterbalance no longer picks too few players because of a player who has just left.

    A team swap that SLM makes is attributed to that swap in the activity feed, rather than showing as the player switching teams on their own.

2026.10.2 (2026-10-20)source

For userssource

  • Added: Ctrl+Enter (Cmd+Enter on a Mac) submits the focused dialog, window or popover, then closes it. Buttons that respond to Ctrl+Enter show the shortcut.

    On the history page, Ctrl+Enter runs the query. In a picker that selects several options, Ctrl+Enter toggles the highlighted option, applies the selection, then closes the picker. It no longer runs the history query behind the picker as well.

  • Added: SLM can generate a vote when the queue runs out. Switch on Generate votes in the Generation tab of Pool Configuration.

    A generated vote offers 3 layers, each on a different map, chosen under the pool's filters and repeat rules. Use Vote Display Options in the same tab to choose what players see for each choice. The map is always shown. When a layer request is pending, SLM still generates the requested layer on its own. When the repeat rules leave fewer than 2 maps, SLM generates a single layer instead.

  • Added: History can show times in UTC, in a server's time zone, or in any IANA time zone.

    Pick one in the new Time zone field. The From and To bounds are entered in the same zone, and saved queries and shared links keep it. The default is still the browser's time zone, and event times now follow it. Before this change they used the SLM host's time zone, while their tooltips used the browser's.

    Two new settings set time zones. timeZone, per server, is UTC by default. defaultTimeZone, global, sets the zone of history links quoted into Discord and of history results a script fetches as text or CSV, when the link or query sets none. By default it is the time zone of the server the events are from. The Discord reply now names the number of events and their time zone.

  • Added: View history in a queue item's menu, or in a match's menu in the match history, opens the queue item's history: every edit to the queue item and who made each edit, the queue item's votes, and the match that played the queue item.

    • A queue save in the activity feed expands to list each edit in the order it was made, with the admin who made each edit.
    • An ended vote shows how many votes each choice received.
    • When a generated layer fulfils layer requests, the activity feed lists each request, who made it and when. A queue item made from layer requests shows them in its history.
    • A layer request made in game names the player who made it instead of their steam id, on the queue item's source and in the layer requests panel.
    • A vote's broadcasts appear under the vote in the activity feed instead of as separate lines. Expand the vote's start to read the announcement and reminders players saw.
    • When an in-game admin sets the next layer, the activity feed shows the in-game change and SLM's response on one line.

  • Added: Rotations can be saved and added to a server's queue in one go. A rotation is an ordered list of layers and votes, with their tags and notes, kept on the new Rotations page.

    Use the Rotations page to search, tag, clone, archive and delete rotations. A rotation's layers are edited the same way as the queue's, and several admins can edit one at once. Each rotation uses a repeat ruleset, and the editor marks layers that break its repeat rules. A rotation's layers can also be edited as YAML or plain text, and copied or downloaded in either format.

    Add Rotation replaces Paste Rotation on the queue. Paste layers on the Paste tab, or pick a saved rotation on the Saved Rotation tab. Pick Replace to replace every layer in the queue. Items added from a saved rotation carry a tag showing the rotation's name.

  • Added: Each team's tickets update live while a match is in progress, in the match history and on the Scoreline chart. Pick Tickets above the Scoreline chart to plot both teams' tickets across the match. Use /tickets in admin chat to see each team's tickets and K/D in game.

    The current match's scoreline and tickets are spoilers now, hidden until Show Spoilers is on. Clicking any hidden value shows every spoiler at once, the teams panel's role, vehicle and K/W/D columns included. Spoilers show by themselves when a match ends, and hide again when the next match starts unless they were shown by hand.

    Matches played before this version show no ticket history.

  • Added: A filter can exempt layers from its miss indicator. An exempt layer does not show the filter's miss emoji or alert message, and SLM does not warn that it misses the filter.

    Set the exempt layers under Miss Indicator when editing a filter's details. Every filter, existing or new, starts out exempting seeding and training layers, so those layers no longer show a filter's miss emoji. SLM already skipped warnings for them.

  • Added: The server activity feed in the player details window can be expanded to fill the window. Use the expand button beside the feed's filter to switch between the feed and the full player details. The This match summary lays out its fields in a row instead of a grid, so it uses less of the window.

  • Added: Automatic vote starts can now be turned on or off, and their delay into the match set, from the Generation & Votes tab of the pool configuration window. The tab was called Generation.

  • Added: The player details window lists the usernames a player has gone by before. Click the history icon beside the username to see each name and the dates it was used.

    A player can also be found by a previous username in the history page's player search.

  • Added: Servers can share repeat rules. Repeat rules are kept in named repeat rulesets, and each server uses one.

    Pick a server's repeat ruleset on the Repeat Rules tab of the pool configuration window, or create or rename one there. Save Changes saves edited rules into the repeat ruleset, so every server using it gets them. A new server gets a repeat ruleset of its own, named after the server.

  • Added: Sandbox Controls can put players in in-game parties. Use the Party column to create a party, move a player into an existing one, or take them out of their party.

  • Added: SLM marks each server with a color. On the server dashboard, the bottom border of the navigation bar takes the color of the server, and the server switcher and server lists show each server in its own color.

    A new server gets a color that stands apart from the existing ones. Existing servers get one on upgrade. Change a server's color under Color in its settings.

  • Added: RCON commands can be run from the server console. Type a command into the box at the bottom of the RCON tab and press Enter. Press Up and Down in the box to step through earlier commands, as in a terminal.

    Running commands requires the new squad-server:write-console permission, which no role holds until an admin grants it. squad-server:view-console still grants reading the console only. Every command run from the console is recorded in the audit log and in the server's activity feed.

    The console no longer has an All tab. The RCON tab shows only commands run from the console until Show SLM requests or Show events is ticked.

  • Added: Teamswaps can counterbalance. With Counterbalance turned on in the swaps panel, SLM queues swaps from the other team whenever an admin queues or removes a swap, so that the teams end up the same size.

    Counterbalance swaps carry a scale icon and a dashed outline. A party is always swapped together, and SLM keeps the players it already picked for as long as the teams need them. If players joining, leaving or switching teams leave the saved swaps uneven, a 2 minute countdown appears in the swaps panel. When it ends, SLM re-picks the counterbalance swaps and records why in the activity feed. Re-pick now and Skip act on the countdown early. Swaps queued with an in-game command are not counterbalanced.

    Use the Teamswap Counterbalance server settings to choose which players are never picked, by group, kills, wounds or K/D, and which players are picked first. Remove a counterbalance swap to have SLM pick a different player.

  • Added: Edits to the queue, saved rotations and filters can be undone and redone.

    Use Undo and Redo beside the reset button, or Ctrl+Z and Ctrl+Y (⌘Z and ⇧⌘Z on a Mac). An undo takes back only your own edits, so other admins editing at the same time keep their edits. After a layer is deleted, the queue is cleared or edits are discarded, SLM shows a message with an Undo button. The reset buttons now show a circular arrow, and the curved arrows now mark undo and redo.

  • Added: The vehicle tables in layer details show each vehicle's ticket value: the tickets its team loses when the enemy destroys it.

    The value comes from the game's own vehicle rules. Vehicles in modded layers do not have a ticket value yet, and show a dash.

  • Added: Line wrapping can be turned off in the server console, the activity panel, the history page's events, and the activity feeds of the player and squad details windows. Use the wrap button beside the search button, or in the toolbar or header above the feed, to turn line wrapping on and off. With wrapping off, each entry stays on one line. In the console, long lines scroll sideways. In the feeds, a line too long for the panel is cut short.

  • Changed: The Filters page can search filters by name or description, narrow the list to one author, and sort it. The search is kept in the page's address, so a filtered view can be linked.

    Filters can be cloned from a filter card's menu or from the filter editor. Right-clicking a filter card opens the same menu.

  • Changed: Admin action reasons are now called message shorthands. Your existing shorthands, and the comments and permissions on them, carry over unchanged.

    The in-game command that lists them is now List Message Shorthands, and keeps its triggers. New installs also get the /shorthands trigger for it.

  • Changed: Repeat rules check a layer against every choice of an earlier vote that has not taken place yet.

    A vote that has not taken place could still play any of its choices, so a layer that repeats any one of them counts as a repeat. Once the vote picks a winner, or ends with too few votes and falls back to its first choice, only the layer the vote settled on counts. An aborted vote can be run again, so all of its choices count again.

  • Changed: Tutorials are split into chapters.

    A step card names its chapter and marks progress through that chapter, in place of the overall step count. The contents group steps by chapter, a card between chapters marks each one finished, and the Tutorials page can start a tutorial from any chapter.

  • Changed: Warn in the player, squad and selection menus opens a dialog, like Kick. Pick a message shorthand or choose Custom to type your own warning.

  • Fixed: In-game commands answer a player whose Steam account an admin linked to somebody who has never signed into SLM.

    SLM sent no reply to any command from such a player, and ran none of them.

  • Fixed: When someone deletes a filter, anyone else viewing that filter is returned to the Filters page, even with unsaved changes, since they can no longer be saved. A toast on the Filters page names who deleted the filter.

  • Fixed: The activity feed shows when a player dies of their wounds. Such a death used to read as a kill made with the victim's own kit.

  • Fixed: Generate Vote follows your server's repeat rules. Hide Repeats is on by default and keeps layers that break a repeat rule out of the choices. With Hide Repeats off, a choice that breaks a repeat rule shows the repeat indicator.

  • Fixed: The history page's Chat contains filter no longer fails with a server error when the text includes punctuation such as !, - or ".

    The filter matches its words as typed, next to each other and in order. NOT, AND and OR are searched for as ordinary words. A player name search of two characters that includes an emoji now finds the matching players.

  • Fixed: On the history page, the clear button beside a text or number filter, such as Match id or Chat contains, now empties the field. Clear All also empties those fields.

  • Fixed: Long broadcasts reach the game in full.

    A broadcast with a very long paragraph lost every line of that paragraph except the overlong ones. A long broadcast written in a non-Latin script, such as Cyrillic, failed to send at all.

  • Fixed: A player whose Epic account changed behind the same Steam account no longer stops SLM from following the roster.

    SLM kept the old link and refused the new one, so team changes, squad changes and new players went unrecorded on that server until the player left. The Steam account now moves to the player's new account.

  • Fixed: Plugin panels that show live data, such as the seed roller's panel on the server dashboard, appear instead of staying empty.

  • Fixed: Panels that plugins add to the server dashboard appear when the page first loads, rather than only after leaving the page and coming back.

  • Fixed: An installed plugin no longer breaks the phone layout. On the Activity tab, the recipient and event filter controls stay on one line above the message box again.

  • Fixed: A queued seeding or training layer ends a repeat rule's lookback, as a played one does.

    A layer queued after a seeding or training layer no longer counts as a repeat of anything before the seeding or training layer. Fix Repeats leaves queued seeding and training layers where they are. The layer table's Hide Repeats no longer hides seeding and training layers, and the layer table no longer marks them as repeats.

  • Fixed: The audit log shows the queue update that records a vote's result.

    When a choice other than the first won a vote, the queue update that applied the result was missing from the audit log. The update also dropped out of the activity feed once SLM restarted or the match ended. The upgrade restores the updates that are already recorded.

  • Fixed: The activity feed and history now record warns and kicks that SLM used to miss.

    A warn was missing when the player's in-game name had just changed, such as a clan tag appearing or disappearing, or a doubled space after the tag. A kick that no admin issued was missing too.

    A kick from SLM no longer counts as refused when the player takes a moment to leave the server. Before, the feed did not show who made such a kick, admins in game were not told about it, and the AFK kicker kicked more players than the queue needed.

  • Fixed: On a phone, the queue's editing controls fit on screen. Save appears where Start Editing was, with Reset beside it, and the tools for adding and changing layers appear in a row below.

  • Fixed: Queue items no longer stay locked after the admin working on them moves on to another item or another browser tab.

For operatorssource

  • Breaking: A plugin that is not built into SLM, tt-slm-plugins included, must be updated for plugin API 0.20, which changes what a layer id is. Update tt-slm-plugins along with SLM.

    SLM now stores a layer id as the layer's name and its two teams in the game's own words, such as Narva_RAAS_v1:USA+CombinedArms:RGF+CombinedArms. SLM rewrites the layer ids it stored before into this form: saved queues, layer requests, rotations and filters as it starts, and match history and the activity feed in the background a few minutes later. Links to a layer written with an old id still open that layer.

    An older SLM cannot read the rewritten ids. To roll back, restore the backup SLM takes before it migrates, as Backups and restoring describes.

  • Breaking: A packed plugin of your own that declares ^0.12 does not load until it is rebuilt against plugin API 0.13.

    The built-in plugins are already updated. For a plugin of your own, set apiVersion to ^0.13 in its manifest and repack it with pnpm plugin:pack. Changes since 0.12:

    • Filters gain missExemption, a filter node or null. Layers that match the node do not show the filter's miss indicator, and null exempts no layer. Filters.create exempts seeding and training layers when missExemption is left out.

  • Breaking: A plugin of your own built for an earlier plugin API does not load until its apiVersion is raised to ^0.19 and it is repacked with pnpm plugin:pack.

    The built-in plugins are already updated. Changes since 0.18:

    • The layer naming functions moved from slm/lib/display-helpers to slm/models/display-helpers. Change a plugin's imports to the new specifier. The functions are unchanged.

  • Breaking: A packed plugin of your own that declares ^0.13 does not load until it is rebuilt against plugin API 0.16.

    The built-in plugins are already updated. For a plugin of your own, set apiVersion to ^0.16 in its manifest and repack it with pnpm plugin:pack. Changes since 0.13:

    • A note copied from a rotation has no author, and its fromRotation names the rotation. A plugin that reads note.author must handle a note without one.
    • A tag id can be from-rotation:<rotationId>, which names no configured tag. A plugin that looks tag ids up in the layer tags must handle one it does not find.
    • A new item passed to add may carry notes, but only notes with no author and a fromRotation.

  • Breaking: A script, settings YAML or plugin that reads or writes queue.mainPool.repeatRules must use the server's repeat ruleset instead. Repeat rules moved from each server's settings into repeat rulesets in the global settings.

    The upgrade migrates the repeat rules automatically. Each server's queue.mainPool.repeatRules becomes a repeat ruleset under the global repeatRulesets setting, named after the server, and the server's settings point at it with queue.mainPool.repeatRulesetId. Tutorial servers share one slm-tutorial repeat ruleset.

  • Added: Plugins can read, create, replace and delete repeat rulesets through slm/systems/repeat-ruleset, and choose which repeat ruleset their server applies. A plugin cannot delete a repeat ruleset that a server or rotation still uses. The audit log records every repeat ruleset change a plugin makes against the plugin.

  • Added: Plugins can search, read, create, clone, update and delete rotations through slm/systems/rotation, and add a rotation to their server's queue the way Add Rotation does. A search returns one page of rotations at a time, without their layers. A plugin's settings can include a rotation tag picker, and a plugin can create layer and rotation tags. When a plugin adds a rotation to the queue, it can clear chosen queue items in the same edit.

    A rotation a plugin creates is owned by the plugin, and the Rotations page names the plugin as its owner. Admins with rotations:write-all can still edit and delete it. A plugin can make an admin the owner instead. The audit log records every rotation change a plugin makes against the plugin. A plugin cannot replace a rotation's layers while an admin has unsaved edits to them open.

  • Changed: Plugins can only be installed and refreshed over https://. SLM also refuses to install a plugin whose id is already installed from another url, and uninstalling a plugin now leaves it stopped if it is installed again.

    A plugin installed from an http:// url can no longer be refreshed. Uninstall it and install it again from its https:// url.

  • Changed: SLM's memory use no longer grows with uptime. Several in-memory buffers and open browser connections kept everything they had ever handled until a restart.

    The RCON PACKET and emitted event log lines are logged at debug instead of info, so production logs at the default level are much smaller.

    SLM looks up a Discord user who has left your guild at most once every 10 minutes, so the warning for that lookup appears far less often. Editing or reordering Discord roles no longer makes SLM recheck every signed-in user's permissions.

    Background BattleMetrics refreshes use at most 45 of the 60 requests a minute that BattleMetrics allows, so requests made by admins are not held behind them.

    The upgrade drops six database indexes that no query reads and adds one for weapon filters on the history page. Expect the migration to take about half a second per million recorded events.

  • Changed: SLM's web interface sends every action over one connection to the server. SLM now refuses that connection when a page on another site opens it, since that page could otherwise act as whoever was signed in. The session cookie is now SameSite=Lax, and Secure when ORIGIN starts with https://.

    A deployment behind a reverse proxy needs ORIGIN set to the url that browsers open, or the proxy must pass the Host header through unchanged. Otherwise the web interface cannot connect.

  • Removed: The RCON Cache TTL server settings are removed. SLM polls each game server at the old defaults: the current and next layer every 5 seconds, server info every 10 seconds and the roster every 5 seconds.

    The upgrade deletes the stored values of these settings and any comments on them. A role's server settings grant that named these settings alongside others keeps the others. A grant that named only these settings becomes a read grant on the same servers, so the role can still view the settings of those servers.

  • Fixed: An admin list whose source cannot be read no longer takes admin status away from everyone on it. SLM keeps the list from its last successful read and logs a warning each time a read fails.

    A remote source that answers with an HTTP error now counts as a failed read, not as an empty list. A list that has not been read successfully since SLM started still grants nothing.

  • Fixed: A top bar colour written to carry markup could run script for anyone who opened SLM's icon in their browser. SLM now draws the icon only from a colour it can read, and serves the icon so that it cannot run script.

  • Fixed: A log line that SLM cannot parse no longer stops SLM reading the server's log. Before, events stopped appearing until SLM was restarted.

    Busy moments no longer stall SLM. A burst of a thousand kills or chat messages, a warn to every player, or a map change held up the rest of SLM for up to a second. Each now holds SLM up for a few tens of milliseconds at most.

  • Fixed: Several security fixes:

    • SLM refuses to be shown inside a frame on another site, which could trick a signed-in admin into clicking its controls.
    • A queue editor can no longer send the queue operations SLM reserves for itself, which skipped the edit window and the pool and installed-mods checks.
    • The plugin list hides the query of an install url, where a token can be kept, and shows a plugin's error only to users who can manage plugins.
    • An open plugin stream stops for a user who loses the permission the plugin requires.
    • SLM refuses to install a plugin whose id is too alike to an installed plugin's for their database tables to be kept apart, such as hello beside hello-x.
    • A server join link must open Steam.

  • Fixed: The server no longer keeps memory for every browser connection it has ever accepted. Each page load used to cost about 9 KB for the life of the process, so a browser stuck reloading grew the server by up to 50 MB an hour.

  • Fixed: A user allowed to edit any one server setting could grant themselves every permission, including plugin installation. SLM now rejects the settings edits that made this possible. Upgrade promptly: the default managers role can edit server settings.

  • Fixed: A user allowed to edit the permissions config or the admin lists could grant themselves any permission. SLM now refuses a save that would grant a permission the user saving it does not hold.

    The raw settings editor no longer lets a user without server-settings:write-sensitive replace a server's connection details while that server's stored settings are invalid.

  • Fixed: A role's server settings grant that is limited to certain settings no longer widens to every setting when an upgrade removes all of the settings it named. The grant now lets the role view those servers' settings and edit none of them.

Smaller fixes and tweaks

  • Added: Plugin API 0.8.1: kickPlayers in slm/systems/squad-server kicks players on behalf of the plugin, and server info now reports reserved slots and the reserved queue.

  • Added: Plugin API 0.8.2: a packed plugin ships a stylesheet, so its Tailwind classes work once installed, and slm/components/ui lends it SLM's alerts, badges, buttons, cards and tooltips.

    pnpm plugin:pack compiles the classes a plugin's client uses into client.css, against SLM's own theme, and SLM loads it with the client. A plain client.css beside client.tsx is compiled into the same file.

  • Added: The overview dashboard in Grafana shows player count and join queue length for each server.

  • Added: Set PUBLIC_DOCS_URL to point the About page's documentation link at your fork's documentation site. Leave it unset to link to SLM's own documentation. The site must be built with SLM's docs build, which lays it out by version.
