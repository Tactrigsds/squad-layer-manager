## [2026.10.1](https://github.com/Tactrigsds/squad-layer-manager/releases/tag/v2026.10.1) (2026-10-05)

### For users

- **Added:** A new AFK Kicker plugin kicks AFK players when people are waiting in the queue.

  A player is AFK after five minutes out of a squad. On seeding and training layers, it is fifteen minutes without doing
  anything instead. It warns AFK players while the server is full, and gives each one a final warning five seconds before the
  kick. A player the game server refuses to kick is left alone until they leave the server. It does nothing between matches, and everyone starts fresh when a new match begins. It is off until you pick the servers it runs on.
- **Added:** Admins can save their own BattleMetrics token, so flags and notes they add show up on BattleMetrics as theirs.

  Open the user menu and choose **BattleMetrics Token**. The dialog links to the BattleMetrics developer page and lists
  the scopes the token needs. Link your Steam account as well, so the flag and note commands you send in game use your
  token too. Without a token, SLM adds flags and notes with your organization's token, as before.
- **Added:** Admins can add notes to a player's BattleMetrics profile and read the notes already there.

  - In the player details window, click the notebook button next to the flag editor to add a note. Click **Load notes**
    to list the player's notes, newest first, with who wrote each one.
  - Right-click a player, a squad or a selection and pick **Add Note...** to add the same note to each of them.
  - In admin chat, type `!note <player> <text>` to add a note.

  SLM posts each note to BattleMetrics signed with the name of the admin who wrote it. SLM fetches a player's notes only
  when **Load notes** is clicked, because each fetch counts against your organization's BattleMetrics request limit.
- **Added:** The Teams Breakdown is now the _Breakdown_ chart in the new _Charts_ panel, beside a new _Scoreline_ chart.

  The _Scoreline_ chart lists each team's tickets, kills, deaths, K/D and wounds, and plots kills, deaths or the kill lead
  across the match. Use the button beside a chart's help icon to open the chart in a window of its own. When a match is
  opened from the match history, a banner above the chart names that match, and _Return to Live_ goes back to the live
  one.
- **Added:** The layer picker has a search box above the results. Type maps, gamemodes, factions, units or filter names, the way `/reqlayer` reads a request.

  The constraint form now opens from the _Advanced_ button beside the search box, and edits the same search. The picker remembers whether _Advanced_ was left open. Submit and the queue options sit along the bottom of the picker.
- **Added:** New player groups and layer tags now start with a color that is easy to tell apart from the ones already in use. Every color picker also offers a row of preset colors.
- **Added:** _Fix Repeats_ in the queue editor reorders the queue and swaps teams to clear repeat warnings.

  It makes as few changes as possible. A tag with _Prevent swaps_ turned on keeps the teams of every layer carrying it.
- **Added:** The teams panel shows the in-game party each player queued with, and the vehicle and seat they are in.

  Party is a grouping mode. Pick Party under Grouping mode to show each player's party in the Group column, color players by party and split the team breakdown chart by party. Players outside a party fall under No party. Filter and sort by party from the Group column. Shift+click a party cell to select that party's members on the same team, or Shift+Ctrl+click to select them on both teams. The player context menu offers the same selection.

  The Vehicle column is a spoiler, shown with Show Spoilers. The player details window shows both the party and the vehicle.
- **Added:** A new _Population_ chart in the _Charts_ panel plots how many players were on the server, split into active and idle players or by team.

  The chart covers the match the panel displays, or every match in the last 6 hours, day or week. A player in a squad or
  in a vehicle is never idle. Anyone else is idle after a set time without doing anything, 10 minutes by default. Click a
  match on the chart to open it. The chart scales to the server's player cap, or to the players drawn. Pick _Stats_ for
  the peak, lowest, average and median player count, the time spent full, the share of idle players, the gap between
  the teams, joins and leaves per hour, and the churn rate over the same time. A chart's own window now opens at the size the chart has in the panel, and the panel shows a
  note with a _Return to panel_ button while the chart is out.
- **Added:** The activity feed shows vehicles and deployables being destroyed, with who destroyed them and who was aboard, and FOB radios coming under attack.

  Destroyed vehicles and deployables appear in the Killfeed filter. Attacks on FOB radios appear in the Default filter: once when an attack starts, and once when the radio is taken down to its minimum health.

  History can search them by the vehicle, the vehicle or deployable type, or the exact blueprint.

  None of these are recorded on training layers such as Jensen's Range. The server setting "Skip Destroyed Vehicles on Training
  Layers" turns that off.
- **Added:** The activity feed and history have a Vehicles & Deployables filter: vehicles and deployables destroyed, and FOB radios under attack.

  The Default filter also shows a vehicle or deployable destroyed by its own side, as it does a teamkill.
- **Added:** A What's new page lists every release and what changed in it. Open it from your account menu.

  A dot on your avatar marks changes you haven't seen yet. "Notify me of" on the page picks which ones: headline
  changes (the default), every change, or nothing. Operator notes only count once you turn them on.
- **Added:** You can queue the four Yehorivka world partitioning layers: AAS, Invasion, RAAS and Skirmish, each `v1_WP`.

  They show as version `V1WP`, so a version filter can pick them out or leave them out. Their balance scores are those of the matching `v1` layer. Vehicle filters and layer details also follow the game's latest vehicle changes, which give every faction's Skirmish units more logistics and transport vehicles.
- **Changed:** The server dashboard stays responsive on a full server. Kills, chat and BattleMetrics updates no longer redraw every player row, and the dashboard no longer freezes for a moment every few minutes.

  SLM opens faster. The first visit downloads about a third less, and pages other than the dashboard are downloaded the first time they are opened. The layer table sorts and filters faster, and a tab left open for days uses less memory.
- **Changed:** A filter can be owned by a plugin or by SLM itself, as well as by an admin. The filter index and the filter's page name the owner.

  A filter that a plugin creates is owned by that plugin. A fresh install's starting filters are owned by SLM, and so is a filter whose admin owner was removed from SLM. Admins with permission to edit every filter, and the filter's contributors, can edit a filter that a plugin or SLM owns.
- **Changed:** The Default filter only shows a FOB radio under attack when its own side is attacking it, as it does for vehicles and deployables.

  Every radio attack shows in the Killfeed and Vehicles & Deployables filters.

  A radio or deployable is also recognised as its side's when the other side's faction name starts the same way, such as PLA against PLAAGF.
- **Changed:** Event searches on the history page load faster, most of all a search for one player's events or for a weapon.

  The history page shows "10,000+ results" for an event search with more than 10,000 results, instead of an exact count.
- **Changed:** When you post a link to a history selection in Discord, SLM now replies with the events as a text file. The reply says how many events and lines it holds and when they happened, in your own time zone.
- **Changed:** The layer indicator tooltip lists one line per issue. Each filter line starts with "In" or "Not in", so an alert for a filter the layer misses no longer reads as a match.

  Repeat lines show how many matches ago the value was played and the gap the rule asks for.
- **Changed:** The filter editor, the settings page, the history page and the Add Layers dialog respond faster. A large filter opens without freezing the page, and typing in the filter editor, a role's settings or a history search no longer lags.

  Number fields in the filter editor and text fields in the history search are saved a quarter of a second after the last keystroke. A search always uses the latest text.

  The layer picker for a "Layer id in" filter starts with an empty filter menu each time it opens. The picker keeps the layers already selected.

  BattleMetrics details for a player open at once, even while SLM is refreshing BattleMetrics data in the background. For a player who is offline, the details shown can be up to a few hours old until the refresh finishes.
- **Changed:** SLM now checks every line pasted into _Paste Rotation_ before adding any layer.

  Each line that fails the check is listed with the layer, faction or unit SLM does not recognise, and the closest name
  it does recognise. A faction or unit its layer cannot be played with is named too. Nothing is added until every listed
  line is fixed or removed. Turn off _Validate layers_ to add such lines anyway, as raw layers.
- **Changed:** On a phone, the layer picker is split into Filters, Results and Summary tabs, and opens on Results.

  - Search for layers by typing maps, gamemodes, factions, units or filter names into the box above the results, the way `/reqlayer` reads a request. Advanced search edits the same search as a full form, vehicles included.
  - Each filter on the Filters tab has an Off, Match or Exclude control.
  - Results can be sorted by any visible column, or put in a random order and rerolled with the dice button.
  - The indicators beside each result open in a sheet. Each filter listed there has a button that opens the filter.
  - The Summary tab lists the selected layers above how they are added to the queue, and holds the Submit button.
  - Pickers open as a sheet along the bottom of the screen, with room for the on-screen keyboard.
- **Changed:** Signing out now ends the session in every tab that has it open, and a user who loses access to SLM is sent back to the sign-in page within a minute. Before, an open tab kept working until it was reloaded.
- **Changed:** Trigger templates take the remaining words with `{{rest}}` instead of a numbered `{{rest2}}`, `{{rest3}}` and so on.

  `{{rest}}` takes every typed word after the highest-numbered `{{argN}}`. Saved triggers are rewritten to use it on
  upgrade. A trigger that used a numbered rest to repeat words an `{{argN}}` already took no longer repeats them.
- **Fixed:** The server dashboard no longer reloads over and over with "The layer pool was updated" after an upgrade, when SLM is served through a CDN such as Cloudflare.
- **Fixed:** The server dashboard on a phone now fits the screen, and a long press opens the menu of a match or a layer.

  - The Matches and Teams screens no longer scroll sideways or cut off on the right. Long squad names are shortened instead.
  - On the Activity screen, the event filter is placed beside the chat channel picker, so the header takes one line.

  - A long press on a layer in the layer picker's results opens its menu.
- **Fixed:** The population chart's 6 hour range now shows a long match that began before the range but ran into it.
- **Fixed:** Kicks that the game server refuses no longer appear in the event feed or on the history page. The game server refuses to kick some players, such as Squad's developers.

### For operators

- **Breaking:** Two changes can need a step when upgrading:

  - **A server agent** is refused while its server still has the default token, `dev`. Set a token of your own in the
    server's connection settings, and give the agent the same one.
  - **A local admin list file** must be inside the `data` directory. Move the file there, or set `LOCAL_ADMIN_LISTS_DIR`
    to the directory it is kept in.
- **Breaking:** The plugin API is version 0.12. A packed plugin that declares `^0.8`, `^0.9`, `^0.10` or `^0.11` does not load until it is rebuilt against 0.12.

  The built-in plugins are already updated. For a plugin of your own, set `apiVersion` to `^0.12` in its manifest and repack it with `pnpm plugin:pack`. Other changes since 0.10:

  - `getServerInfo` and `getLayerStatus` in `slm/systems/squad-rcon` answer from SLM's cache, as `getTeams` does, instead of sending an RCON command on every call. A plugin that calls them often no longer adds RCON traffic.
  - `getTeams`, `getServerInfo`, `getLayerStatus` and `getPlayer` take an optional `{ ttl }` in milliseconds, for an answer fresher than the cache. A `ttl` below `MIN_TTL_MS` (1 second) is raised to it.
  - `teams$`, `serverInfo$` and `layerStatus$` push every new answer to a plugin, so a plugin no longer has to poll.
  - The player objects that `getPlayer`, `getTeams` and `checkPlayer` work with can carry `partyId` and `vehicle`.
  - `tryKickPlayers` in `slm/systems/squad-server` kicks players like `kickPlayers` and returns the players the game server kicked.
  - `slm/lib/rxjs-ext` adds `bufferBurst`.
  - `slm/systems/player-activity` reads SLM's rule for when a player counts as idle.
  - `register` in `slm/systems/post-roll-reminders` takes the per-server ctx and must be called from `Servers.setup`. The provider takes no arguments. A provider registered for one server is asked only after rolls on that server.
- **Breaking:** A plugin that creates filters, or reads a filter's owner, needs a code change for plugin API 0.12. A filter's `owner` is now `{ type: 'slm-user', userId }`, `{ type: 'plugin', pluginId }` or `{ type: 'system' }` instead of a discord user id.

  `create` in `slm/systems/filter-entity` makes the calling plugin the filter's owner. To keep an admin as the owner, pass `owner: { type: 'slm-user', userId }`.

  The upgrade hands SLM's starting filters, and any filter whose owner was removed from SLM, to SLM itself. Filters an admin owns stay theirs.
- **Breaking:** The BattleMetrics, Squad Browser and Steam credentials move from the environment to the settings page. The encryption key can be rotated, must be at least 16 characters in production, and credentials can be mounted one file each.

  **Integrations on the settings page.** `BM_PAT`, `BM_ORG_ID`, `BM_ENABLED`, `SQUADBROWSER_API_KEY`, `SQUADBROWSER_ENABLED`, `STEAM_API_KEY` and `STEAM_ENABLED` are now the _Integrations_ section of the global settings. The first boot after upgrading carries the values over from the environment into the settings, after which the variables are ignored and the boot log says so each time one is still set. Remove them from `.env` and `.env.secrets` once that boot has happened. A token is stored encrypted and never shown again: the field shows a placeholder, and typing in it replaces the token. Editing the section takes a `global-settings:write` grant on `integrations`, which the default managers role does not hold. `BM_HOST`, `SQUADBROWSER_HOST` and `STEAM_HOST` stay in the environment.

  **Encryption key length.** Production refuses a `SETTINGS_ENCRYPTION_KEY` shorter than 16 characters. If yours is, move it to `SETTINGS_ENCRYPTION_KEY_PREVIOUS`, generate a new one with `openssl rand -base64 32` into `SETTINGS_ENCRYPTION_KEY`, and start the app. A key from `install.sh` or from that command is long enough already and needs nothing.

  **Key rotation.** `SETTINGS_ENCRYPTION_KEY_PREVIOUS` is the rotation path in general. On the next boot everything still encrypted with the old key is re-encrypted with the new one, after which the variable can be removed.

  **One file per credential.** `SECRETS_DIR` reads credentials from a directory holding one file per variable, which is what docker and podman secrets, a kubernetes secret volume and systemd's credentials directory mount. A file there wins over the same variable in `SECRETS_FILE`.

  **Restore.** `restore.sh --inspect` now also reports whether a backup's secrets decrypt with the key configured here, since a backup restored under a different key comes up with its servers disabled and its integration tokens unset.
- **Added:** An announcement can count down to a time. Put `{countdown:2m}` in the message passed to `pnpm announce`, and the web banner counts down from 2 minutes. The in-game warn is sent once and shows "2m".
- **Added:** `install.sh` installs the newest release by default. Pass `--channel latest` to follow every change, or `--version 2026.9.4` to pin one release.

  The choice is saved as `SLM_IMAGE_TAG` in `.env`, and `docker-compose.yaml` reads the image tag from it. To switch
  channel or pin a build, change `SLM_IMAGE_TAG` and run `docker compose pull && docker compose up -d`. The installer
  also fetches the files for the release it installs, so `docker-compose.yaml` and `.env.example` match the image.

  An existing install keeps following `:latest` and needs no change. To set its tag from `.env`, change the `image:`
  line of the `app` service in `docker-compose.yaml` to `ghcr.io/tactrigsds/squad-layer-manager:${SLM_IMAGE_TAG:-latest}`.
- **Added:** Plugins can depend on packages from npm. `pnpm plugin:pack` bundles them into the plugin.

  A plugin repo declares its dependencies in its own `package.json` and installs them with `pnpm install`. The packages
  SLM provides now include `react-dom`. `pnpm plugin:pack` refuses CommonJS packages, and warns when a dependency
  expects a version of `react`, `zod` or another provided package that SLM does not ship. The plugin guide's
  _Dependencies_ section describes the setup.
- **Added:** SLM refuses to start on a database a newer build has migrated, instead of running against a schema it does not know.

  The log names the migrations the running build is missing and the image tag of the build that last ran against the
  database. To go back to an older build, restore a backup taken before the upgrade, as _Downgrading_ in the install
  guide describes.
- **Added:** Releases are published as a `:stable` image tag, alongside a tag for each version. `:latest` still follows every change.

  Follow `:stable` for tested batches of changes that come with release notes. See the upgrading section of docs/installing.md.
- **Changed:** The password of an SFTP admin list source is now treated as a credential. SLM encrypts the password in the database, and hides it on the settings page and in the audit log.

  The first start after upgrading encrypts a stored password in place. A version older than this one reads the encrypted
  value as the password, so downgrading needs the password entered again.
- **Changed:** Backups are smaller and take less time. A backup copies only the data your database holds, without the free space a database file keeps after old data is deleted. On a 2.5 GB production database with 1.9 GB of free space, a backup shrank from 447 MB to 107 MB and took 14 seconds instead of 57.

  A database restored from one of these backups is compacted the same way, so its file is smaller than the one it was taken from.

  Recording game events no longer stalls SLM for 10 to 20 ms every few hundred events.
- **Changed:** A new permission, `battlemetrics:write-notes`, controls who can add BattleMetrics notes.

  The upgrade grants `battlemetrics:write-notes` to every role that has `battlemetrics:write-flags`, and denies it to
  every role that denies `battlemetrics:write-flags`. Remove `battlemetrics:write-notes` from a role to stop that role
  adding notes without affecting its flags.
- **Changed:** The database file now shrinks on its own as old data is removed, instead of keeping the freed space for good.

  The first start after upgrading compacts the database once, before SLM begins serving. A 2.5 GB production database, three quarters of it free space, took 3 seconds and came out at 545 MB. Compacting needs free disk space about the size of the compacted database while it runs. With `DB_AUTOMIGRATE` off, `pnpm db:migrate` does the compacting instead.
- **Changed:** Plugins cannot be installed or refreshed from a url on a demo instance. Anyone who reaches a demo signs in as an admin, so installing a plugin there would let anyone run code on the server.

  The demo command in the installation guide now accepts connections from the local machine only.
- **Changed:** SLM runs as the unprivileged `node` user inside its container. The first start after upgrading hands the `data` directory to that user, so no step is needed.

  Session ids are stored hashed, so a copy of the database or a backup no longer holds a usable sign-in. Nobody is signed
  out by the upgrade.

  Grafana now asks everyone to sign in, and accepts connections from the machine SLM runs on only. An existing install
  keeps its Grafana admin account and password. To open Grafana from another machine, forward port 3001 over SSH with
  `ssh -L 3001:localhost:3001 <your server>`, or put it behind a reverse proxy on the same machine.
- **Changed:** SLM starts answering requests sooner after a restart. With _Warn on SLM Start_ turned on, a game server that SLM cannot reach no longer delays startup by about 15 seconds.
- **Changed:** Replies to history links in Discord now always attach a file. Give the bot's role Attach Files in every channel where it should reply. Without it, SLM does not reply there.
- **Changed:** Use the new _Player Activity_ setting under _Players & Balance_ to set how long a player can go without doing anything before SLM counts them as idle.

  The AFK Kicker follows SLM's idle rule on its idle gamemodes, so it no longer kicks an inactive player who is in a squad
  or in a vehicle there. The kicker's `idleWindow` setting still decides how long a player stays idle before the kicker
  acts. Plugins can read
  the same rule from `slm/systems/player-activity` (plugin API 0.12).

  After the upgrade, SLM counts the players of every past match in the background, newest first, for the chart's day and
  week ranges. Until a match is counted, the chart notes how many in its range are still missing.
- **Changed:** Plugins can only be installed and refreshed over `https://`. SLM also refuses to install a plugin whose id is already installed from another url, and uninstalling a plugin now leaves it stopped if it is installed again.

  A plugin installed from an `http://` url can no longer be refreshed. Uninstall it and install it again from its
  `https://` url.
- **Changed:** SLM's memory use no longer grows with uptime. Several in-memory buffers and open browser connections kept everything they had ever handled until a restart.

  The `RCON PACKET` and `emitted event` log lines are logged at `debug` instead of `info`, so production logs at the default level are much smaller.

  SLM looks up a Discord user who has left your guild at most once every 10 minutes, so the warning for that lookup appears far less often. Editing or reordering Discord roles no longer makes SLM recheck every signed-in user's permissions.

  Background BattleMetrics refreshes use at most 45 of the 60 requests a minute that BattleMetrics allows, so requests made by admins are not held behind them.

  The upgrade drops six database indexes that no query reads and adds one for weapon filters on the history page. Expect the migration to take about half a second per million recorded events.
- **Changed:** SLM's web interface sends every action over one connection to the server. SLM now refuses that connection when a page on another site opens it, since that page could otherwise act as whoever was signed in. The session cookie is now `SameSite=Lax`, and `Secure` when `ORIGIN` starts with `https://`.

  A deployment behind a reverse proxy needs `ORIGIN` set to the url that browsers open, or the proxy must pass the `Host`
  header through unchanged. Otherwise the web interface cannot connect.
- **Removed:** The _RCON Cache TTL_ server settings are removed. SLM polls each game server at the old defaults: the current and next layer every 5 seconds, server info every 10 seconds and the roster every 5 seconds.

  The upgrade deletes the stored values of these settings and any comments on them. A role's server settings grant that named these settings alongside others keeps the others. A grant that named only these settings becomes a read grant on the same servers, so the role can still view the settings of those servers.
- **Fixed:** An admin list whose source cannot be read no longer takes admin status away from everyone on it. SLM keeps the list from its last successful read and logs a warning each time a read fails.

  A remote source that answers with an HTTP error now counts as a failed read, not as an empty list. A list that has not been read successfully since SLM started still grants nothing.
- **Fixed:** A top bar colour written to carry markup could run script for anyone who opened SLM's icon in their browser. SLM now draws the icon only from a colour it can read, and serves the icon so that it cannot run script.
- **Fixed:** A log line that SLM cannot parse no longer stops SLM reading the server's log. Before, events stopped appearing until SLM was restarted.

  Busy moments no longer stall SLM. A burst of a thousand kills or chat messages, a warn to every player, or a map change held up the rest of SLM for up to a second. Each now holds SLM up for a few tens of milliseconds at most.
- **Fixed:** Several security fixes:

  - SLM refuses to be shown inside a frame on another site, which could trick a signed-in admin into clicking its
    controls.
  - A queue editor can no longer send the queue operations SLM reserves for itself, which skipped the edit window and the
    pool and installed-mods checks.
  - The plugin list hides the query of an install url, where a token can be kept, and shows a plugin's error only to
    users who can manage plugins.
  - An open plugin stream stops for a user who loses the permission the plugin requires.
  - SLM refuses to install a plugin whose id is too alike to an installed plugin's for their database tables to be kept
    apart, such as `hello` beside `hello-x`.
  - A server join link must open Steam.
- **Fixed:** The server no longer keeps memory for every browser connection it has ever accepted. Each page load used to cost about 9 KB for the life of the process, so a browser stuck reloading grew the server by up to 50 MB an hour.
- **Fixed:** A user allowed to edit any one server setting could grant themselves every permission, including plugin installation. SLM now rejects the settings edits that made this possible. Upgrade promptly: the default managers role can edit server settings.
- **Fixed:** A user allowed to edit the permissions config or the admin lists could grant themselves any permission. SLM now refuses a save that would grant a permission the user saving it does not hold.

  The raw settings editor no longer lets a user without `server-settings:write-sensitive` replace a server's connection
  details while that server's stored settings are invalid.
- **Fixed:** A role's server settings grant that is limited to certain settings no longer widens to every setting when an upgrade removes all of the settings it named. The grant now lets the role view those servers' settings and edit none of them.
