## [2026.10.5](https://github.com/Tactrigsds/squad-layer-manager/releases/tag/v2026.10.5) (2026-10-27)

### For users

- **Fixed:** A vote can be saved without a false _Filter Warnings_ alert. The alert called the vote's default choice "not in the pool" even when the choice was in it, so the vote could only be saved with _Save Anyway_. When a vote is the next layer, the in-game next layer message to admins now lists the repeat rules and pool filters that the vote's current choice breaks.

   In _Gen Vote_, clicking the placement option that is already selected keeps it selected. Clicking it used to select the other option.

- **Fixed:** SLM no longer misses a next layer set in the seconds after a match starts.

   An admin could set a next layer while the new match was loading, or while SLM was reconnecting to the server. SLM then neither added that layer to the queue nor overrode it. SLM now handles that change like any other.

   When the connection to the server dropped as SLM was setting the next layer, the server kept its old next layer. SLM now sets the first item in the queue once the connection is back.

   The match history showed `(???)` as the length of a match that lasted under a minute. It now shows `1m`.

- **Fixed:** The next layer no longer drifts off the queue after an admin changes it from outside SLM.

   With _Override the next layer when it is set outside SLM_ on, SLM sometimes let an outside change stand. After a match that was not the first item in the queue, SLM also left the server's own rotation to pick the following layer. SLM now sets the first item in the queue as the next layer in both cases.

- **Fixed:** The pool settings on the dashboard save every filter change. Changing whether a filter in Warn For, Constrain Generation or Layer Request Filters applies as regular or inverted no longer fails with an error.
- **Fixed:** Votes start on their own again. When the next item in the queue is a vote, SLM starts it once the match reaches the Auto Start Vote Delay, and leaves it to an admin after the Auto Start Vote Cutoff.

## [2026.10.4](https://github.com/Tactrigsds/squad-layer-manager/releases/tag/v2026.10.4) (2026-10-21)

### For users

- **Added:** Layer tables summarize the layers that match your filters.

   Each column with a fixed set of values, such as Map or Unit, shows in its header how many different values the matching
   layers hold. Hover over the header to see those values and how many layers hold each one. Hover over a score column's
   header to see the lowest and highest score among the matching layers.

   Switch to _Summary_ beside the matched layers count to see every column's values at once, the score ranges, and how many
   layers each filter matches or removes.

- **Changed:** Presence lists show one avatar per user. Another of your tabs or devices appears separately only while it is editing.

   The warning about your other sessions appears only when one of those sessions is editing. Its button, now _Stop editing there_, ends their editing sessions. The warning also says when stopping them discards unsaved edits, which happens when no one else is editing the same thing.

- **Changed:** Dragging a queue item or a layer request is easier to aim. Drop it anywhere between the middles of two items to move it there, or on the area at the end of another item to make a vote from the two queue items, or to combine the two requests.

   Dropping on a layer's name no longer creates a vote, and dropping on a request's description no longer combines requests. The _Create Vote_ and _Combine_ areas appear while an item is dragged. To move an item to the top of its list, release it anywhere between the list's header and the middle of the first item. A dragged queue item is shown faded rather than as an empty box.

- **Changed:** SuperMod layers match SuperMod's current release. The Belaya, Chornivsk, Hrodna Border and Rassvet maps are added, and the Johat, Khokhan, Mogadishu and OP First Light layers that SuperMod no longer ships are removed.

   Each SuperMod layer takes its map and gamemode from SuperMod's own data, which is what the game loads. A GoingDark or
   Large variant shares its map with the layer it is built on: _SU_GoingDark_Tallil_RAAS_v1_ is on Tallil, and
   _SU_Chora_LargeInvasion_v1_ on Chora. _SU_Tallil_SeedVehicle_v1_ is a Seed layer, _SU_GoingDark_Narva_RAAS_v1_ a RAAS
   PreCap layer, and _SU_GoingDark_Narva_RVAAS_v1_ a RAAS layer.

   GoingDark layers, SuperMod's night layers, carry a GD version, such as V1GD for _SU_GoingDark_Narva_RAAS_v1_, the way a
   world-partitioned layer carries WP. A filter on the version can include or exclude them.

   Some vehicles that only SuperMod ships are renamed to the names SuperMod now gives them, such as _Mi8 CAS_ for _Mi-8
   CAS_. A filter on a vehicle's old name no longer matches it, so check vehicle filters for SuperMod vehicles.

   Vehicles that vanilla Squad also ships take their class from vanilla Squad. The BRDM-2 is a light vehicle and the
   Technical BMP-1 a tank destroyer again, and the CH-146 CAS is an attack helicopter.

- **Removed:** Resurgence and Galactic Contention layers are no longer in the layer catalog, because neither mod has been updated for Squad v10.6. They return once each mod is updated.

   A queue item on one of their layers stays in the queue, marked as an unknown layer. A server whose _Installed Mods_
   names either mod lists it as not in the catalog.

- **Fixed:** The layer table no longer fails with "Error loading layers" after the server moves to new layer data.
- **Fixed:** SLM no longer signs you out a week after you sign in while you are still using it. SLM now signs you out only after 6 days without a visit, and an open tab counts as a visit.
- **Fixed:** The vehicle tables in layer details show each vehicle's ticket value. Since 2026.10.2 the column showed a dash for every vehicle.

   An RCON command no longer times out while it waits behind other commands, and no longer receives the reply to a different command.

## [2026.10.2](https://github.com/Tactrigsds/squad-layer-manager/releases/tag/v2026.10.2) (2026-10-20)

### For users

- **Added:** Ctrl+Enter (Cmd+Enter on a Mac) submits the focused dialog, window or popover, then closes it. Buttons that respond to Ctrl+Enter show the shortcut.

   On the history page, Ctrl+Enter runs the query. In a picker that selects several options, Ctrl+Enter toggles the
   highlighted option, applies the selection, then closes the picker. It no longer runs the history query behind the
   picker as well.

- **Added:** SLM can generate a vote when the queue runs out. Switch on _Generate votes_ in the _Generation_ tab of _Pool Configuration_.

   A generated vote offers 3 layers, each on a different map, chosen under the pool's filters and repeat rules. Use _Vote Display Options_ in the same tab to choose what players see for each choice. The map is always shown. When a layer request is pending, SLM still generates the requested layer on its own. When the repeat rules leave fewer than 2 maps, SLM generates a single layer instead.

- **Added:** History can show times in UTC, in a server's time zone, or in any IANA time zone.

   Pick one in the new _Time zone_ field. The _From_ and _To_ bounds are entered in the same zone, and saved queries and
   shared links keep it. The default is still the browser's time zone, and event times now follow it. Before this change
   they used the SLM host's time zone, while their tooltips used the browser's.

   Two new settings set time zones. `timeZone`, per server, is UTC by default. `defaultTimeZone`, global, sets the zone of
   history links quoted into Discord and of history results a script fetches as text or CSV, when the link or query sets
   none.
   By default it is the time zone of the server the events are from. The Discord reply now names the number of events and
   their time zone.

- **Added:** _View history_ in a queue item's menu, or in a match's menu in the match history, opens the queue item's history: every edit to the queue item and who made each edit, the queue item's votes, and the match that played the queue item.

   - A queue save in the activity feed expands to list each edit in the order it was made, with the admin who made each
     edit.
   - An ended vote shows how many votes each choice received.
   - When a generated layer fulfils layer requests, the activity feed lists each request, who made it and when. A queue
     item made from layer requests shows them in its history.
   - A layer request made in game names the player who made it instead of their steam id, on the queue item's source
     and in the layer requests panel.
   - A vote's broadcasts appear under the vote in the activity feed instead of as separate lines. Expand the vote's start to
     read the announcement and reminders players saw.
   - When an in-game admin sets the next layer, the activity feed shows the in-game change and SLM's response on one line.

- **Added:** Rotations can be saved and added to a server's queue in one go. A rotation is an ordered list of layers and votes, with their tags and notes, kept on the new _Rotations_ page.

   Use the _Rotations_ page to search, tag, clone, archive and delete rotations. A rotation's layers are edited the same
   way as the queue's, and several admins can edit one at once. Each rotation uses a repeat ruleset, and the editor marks layers
   that break its repeat rules. A rotation's layers can also be edited as YAML or plain text, and copied or downloaded in
   either format.

   _Add Rotation_ replaces _Paste Rotation_ on the queue. Paste layers on the _Paste_ tab, or pick a saved rotation on the
   _Saved Rotation_ tab. Pick _Replace_ to replace every layer in the queue. Items added from a saved rotation carry a tag
   showing the rotation's name.

- **Added:** Each team's tickets update live while a match is in progress, in the match history and on the _Scoreline_ chart. Pick _Tickets_ above the _Scoreline_ chart to plot both teams' tickets across the match. Use `/tickets` in admin chat to see each team's tickets and K/D in game.

   The current match's scoreline and tickets are spoilers now, hidden until _Show Spoilers_ is on. Clicking any hidden
   value shows every spoiler at once, the teams panel's role, vehicle and K/W/D columns included. Spoilers show by
   themselves when a match ends, and hide again when the next match starts unless they were shown by hand.

   Matches played before this version show no ticket history.

- **Added:** A filter can exempt layers from its miss indicator. An exempt layer does not show the filter's miss emoji or alert message, and SLM does not warn that it misses the filter.

   Set the exempt layers under _Miss Indicator_ when editing a filter's details. Every filter, existing or new, starts out exempting seeding and training layers, so those layers no longer show a filter's miss emoji. SLM already skipped warnings for them.

- **Added:** The server activity feed in the player details window can be expanded to fill the window. Use the expand button beside the feed's filter to switch between the feed and the full player details. The _This match_ summary lays out its fields in a row instead of a grid, so it uses less of the window.
- **Added:** Automatic vote starts can now be turned on or off, and their delay into the match set, from the _Generation & Votes_ tab of the pool configuration window. The tab was called _Generation_.
- **Added:** The player details window lists the usernames a player has gone by before. Click the history icon beside the username to see each name and the dates it was used.

   A player can also be found by a previous username in the history page's player search.

- **Added:** Servers can share repeat rules. Repeat rules are kept in named repeat rulesets, and each server uses one.

   Pick a server's repeat ruleset on the _Repeat Rules_ tab of the pool configuration window, or create or rename one
   there. _Save Changes_ saves edited rules into the repeat ruleset, so every server using it gets them. A new server gets
   a repeat ruleset of its own, named after the server.

- **Added:** Sandbox Controls can put players in in-game parties. Use the Party column to create a party, move a player into an existing one, or take them out of their party.
- **Added:** SLM marks each server with a color. On the server dashboard, the bottom border of the navigation bar takes the color of the server, and the server switcher and server lists show each server in its own color.

   A new server gets a color that stands apart from the existing ones. Existing servers get one on upgrade. Change a server's color under _Color_ in its settings.

- **Added:** RCON commands can be run from the server console. Type a command into the box at the bottom of the RCON tab and press Enter. Press Up and Down in the box to step through earlier commands, as in a terminal.

   Running commands requires the new `squad-server:write-console` permission, which no role holds until an admin grants
   it. `squad-server:view-console` still grants reading the console only. Every command run from the console is recorded
   in the audit log and in the server's activity feed.

   The console no longer has an **All** tab. The RCON tab shows only commands run from the console until **Show SLM
   requests** or **Show events** is ticked.

- **Added:** Teamswaps can counterbalance. With _Counterbalance_ turned on in the swaps panel, SLM queues swaps from the other team whenever an admin queues or removes a swap, so that the teams end up the same size.

   Counterbalance swaps carry a scale icon and a dashed outline. A party is always swapped together, and SLM keeps the players it already picked for as long as the teams need them. If players joining, leaving or switching teams leave the saved swaps uneven, a 2 minute countdown appears in the swaps panel. When it ends, SLM re-picks the counterbalance swaps and records why in the activity feed. _Re-pick now_ and _Skip_ act on the countdown early. Swaps queued with an in-game command are not counterbalanced.

   Use the _Teamswap Counterbalance_ server settings to choose which players are never picked, by group, kills, wounds or K/D, and which players are picked first. Remove a counterbalance swap to have SLM pick a different player.

- **Added:** Edits to the queue, saved rotations and filters can be undone and redone.

   Use _Undo_ and _Redo_ beside the reset button, or Ctrl+Z and Ctrl+Y (⌘Z and ⇧⌘Z on a Mac). An undo takes back only
   your own edits, so other admins editing at the same time keep their edits. After a layer is deleted, the queue is
   cleared or edits are discarded, SLM shows a message with an _Undo_ button. The reset buttons now show a circular
   arrow, and the curved arrows now mark undo and redo.

- **Added:** The vehicle tables in layer details show each vehicle's ticket value: the tickets its team loses when the enemy destroys it.

   The value comes from the game's own vehicle rules. Vehicles in modded layers do not have a ticket value yet, and show a
   dash.

- **Added:** Line wrapping can be turned off in the server console, the activity panel, the history page's events, and the activity feeds of the player and squad details windows. Use the wrap button beside the search button, or in the toolbar or header above the feed, to turn line wrapping on and off. With wrapping off, each entry stays on one line. In the console, long lines scroll sideways. In the feeds, a line too long for the panel is cut short.
- **Changed:** The _Filters_ page can search filters by name or description, narrow the list to one author, and sort it. The search is kept in the page's address, so a filtered view can be linked.

   Filters can be cloned from a filter card's menu or from the filter editor. Right-clicking a filter card opens the same
   menu.

- **Changed:** Admin action reasons are now called message shorthands. Your existing shorthands, and the comments and permissions on them, carry over unchanged.

   The in-game command that lists them is now _List Message Shorthands_, and keeps its triggers. New installs also get
   the `/shorthands` trigger for it.

- **Changed:** Repeat rules check a layer against every choice of an earlier vote that has not taken place yet.

   A vote that has not taken place could still play any of its choices, so a layer that repeats any one of them counts as a repeat. Once the vote picks a winner, or ends with too few votes and falls back to its first choice, only the layer the vote settled on counts. An aborted vote can be run again, so all of its choices count again.

- **Changed:** Tutorials are split into chapters.

   A step card names its chapter and marks progress through that chapter, in place of the overall step count. The
   contents group steps by chapter, a card between chapters marks each one finished, and the _Tutorials_ page can start a
   tutorial from any chapter.

- **Changed:** _Warn_ in the player, squad and selection menus opens a dialog, like _Kick_. Pick a message shorthand or choose _Custom_ to type your own warning.
- **Fixed:** In-game commands answer a player whose Steam account an admin linked to somebody who has never signed into SLM.

   SLM sent no reply to any command from such a player, and ran none of them.

- **Fixed:** When someone deletes a filter, anyone else viewing that filter is returned to the _Filters_ page, even with unsaved changes, since they can no longer be saved. A toast on the _Filters_ page names who deleted the filter.
- **Fixed:** The activity feed shows when a player dies of their wounds. Such a death used to read as a kill made with the victim's own kit.
- **Fixed:** Generate Vote follows your server's repeat rules. _Hide Repeats_ is on by default and keeps layers that break a repeat rule out of the choices. With _Hide Repeats_ off, a choice that breaks a repeat rule shows the repeat indicator.
- **Fixed:** The history page's _Chat contains_ filter no longer fails with a server error when the text includes punctuation such as `!`, `-` or `"`.

   The filter matches its words as typed, next to each other and in order. `NOT`, `AND` and `OR` are searched for as
   ordinary words. A player name search of two characters that includes an emoji now finds the matching players.

- **Fixed:** On the history page, the clear button beside a text or number filter, such as _Match id_ or _Chat contains_, now empties the field. _Clear All_ also empties those fields.
- **Fixed:** Long broadcasts reach the game in full.

   A broadcast with a very long paragraph lost every line of that paragraph except the overlong ones. A long broadcast
   written in a non-Latin script, such as Cyrillic, failed to send at all.

- **Fixed:** A player whose Epic account changed behind the same Steam account no longer stops SLM from following the roster.

   SLM kept the old link and refused the new one, so team changes, squad changes and new players went unrecorded on
   that server until the player left. The Steam account now moves to the player's new account.

- **Fixed:** Plugin panels that show live data, such as the seed roller's panel on the server dashboard, appear instead of staying empty.
- **Fixed:** Panels that plugins add to the server dashboard appear when the page first loads, rather than only after leaving the page and coming back.
- **Fixed:** An installed plugin no longer breaks the phone layout. On the Activity tab, the recipient and event filter controls stay on one line above the message box again.
- **Fixed:** A queued seeding or training layer ends a repeat rule's lookback, as a played one does.

   A layer queued after a seeding or training layer no longer counts as a repeat of anything before the seeding or training layer. _Fix Repeats_ leaves queued seeding and training layers where they are. The layer table's _Hide Repeats_ no longer hides seeding and training layers, and the layer table no longer marks them as repeats.

- **Fixed:** The audit log shows the queue update that records a vote's result.

   When a choice other than the first won a vote, the queue update that applied the result was missing from the audit
   log. The update also dropped out of the activity feed once SLM restarted or the match ended. The upgrade restores the updates
   that are already recorded.

- **Fixed:** The activity feed and history now record warns and kicks that SLM used to miss.

   A warn was missing when the player's in-game name had just changed, such as a clan tag appearing or disappearing,
   or a doubled space after the tag. A kick that no admin issued was missing too.

   A kick from SLM no longer counts as refused when the player takes a moment to leave the server. Before, the feed did not
   show who made such a kick, admins in game were not told about it, and the AFK kicker kicked more players than the
   queue needed.

### For operators

- **Breaking:** A plugin that is not built into SLM, tt-slm-plugins included, must be updated for plugin API 0.20, which changes what a layer id is. Update tt-slm-plugins along with SLM.

   SLM now stores a layer id as the layer's name and its two teams in the game's own words, such as
   `Narva_RAAS_v1:USA+CombinedArms:RGF+CombinedArms`. SLM rewrites the layer ids it stored before into this form: saved
   queues, layer requests, rotations and filters as it starts, and match history and the activity feed in the background
   a few minutes later.
   Links to a layer written with an old id still open that layer.

   An older SLM cannot read the rewritten ids. To roll back, restore the backup SLM takes before it migrates, as
   [Backups and restoring](https://tactrigsds.github.io/squad-layer-manager/2026.10.2/backups/) describes.

- **Breaking:** A packed plugin of your own that declares `^0.12` does not load until it is rebuilt against plugin API 0.13.

   The built-in plugins are already updated. For a plugin of your own, set `apiVersion` to `^0.13` in its manifest and repack it with `pnpm plugin:pack`. Changes since 0.12:

   - Filters gain `missExemption`, a filter node or null. Layers that match the node do not show the filter's miss indicator, and null exempts no layer. `Filters.create` exempts seeding and training layers when `missExemption` is left out.

- **Breaking:** A plugin of your own built for an earlier plugin API does not load until its `apiVersion` is raised to `^0.19` and it is repacked with `pnpm plugin:pack`.

   The built-in plugins are already updated. Changes since 0.18:

   - The layer naming functions moved from `slm/lib/display-helpers` to `slm/models/display-helpers`. Change a plugin's
     imports to the new specifier. The functions are unchanged.

- **Breaking:** A packed plugin of your own that declares `^0.13` does not load until it is rebuilt against plugin API 0.16.

   The built-in plugins are already updated. For a plugin of your own, set `apiVersion` to `^0.16` in its manifest and
   repack it with `pnpm plugin:pack`. Changes since 0.13:

   - A note copied from a rotation has no `author`, and its `fromRotation` names the rotation. A plugin that reads
     `note.author` must handle a note without one.
   - A tag id can be `from-rotation:<rotationId>`, which names no configured tag. A plugin that looks tag ids up in the
     layer tags must handle one it does not find.
   - A new item passed to `add` may carry notes, but only notes with no `author` and a `fromRotation`.

- **Breaking:** A script, settings YAML or plugin that reads or writes `queue.mainPool.repeatRules` must use the server's repeat ruleset instead. Repeat rules moved from each server's settings into repeat rulesets in the global settings.

   The upgrade migrates the repeat rules automatically. Each server's `queue.mainPool.repeatRules` becomes a repeat
   ruleset under the global `repeatRulesets` setting, named after the server, and the server's settings point at it with

- **Changed:** A new permission, `battlemetrics:write-notes`, controls who can add BattleMetrics notes.

   The upgrade grants `battlemetrics:write-notes` to every role that has `battlemetrics:write-flags`, and denies it to
   every role that denies `battlemetrics:write-flags`. Remove `battlemetrics:write-notes` from a role to stop that role
   adding notes without affecting its flags.

- **Changed:** The database file now shrinks on its own as old data is removed, instead of keeping the freed space for good.

   The first start after upgrading compacts the database once, before SLM begins serving. A 2.5 GB production database, three quarters of it free space, took 3 seconds and came out at 545 MB. Compacting needs free disk space about the size of the compacted database while it runs. With `DB_AUTOMIGRATE` off, `pnpm db:migrate` does the compacting instead.

- **Changed:** Plugins cannot be installed or refreshed from a url on a demo instance. Anyone who reaches a demo signs in as an admin, so installing a plugin there would let anyone run code on the server.

   The demo command in the installation guide now accepts connections from the local machine only.

- **Changed:** SLM runs as the unprivileged `node` user inside its container. The first start after upgrading hands the `data` directory to that user, so no step is needed.

   Session ids are stored hashed, so a copy of the database or a backup no longer holds a usable sign-in. Nobody is signed
   out by the upgrade.

   Grafana now asks everyone to sign in, and accepts connections from the machine SLM runs on only. An existing install
   keeps its Grafana admin account and password. To open Grafana from another machine, forward port 3001 over SSH with
   `ssh -L 3001:localhost:3001 <your server>`, or put it behind a reverse proxy on the same machine.

- **Changed:** SLM starts answering requests sooner after a restart. With _Warn on SLM Start_ turned on, a game server that SLM cannot reach no longer delays startup by about 15 seconds.
- **Changed:** Replies to history links in Discord now always attach a file. Give the bot's role Attach Files in every channel where it should reply. Without it, SLM does not reply there.
- **Changed:** Use the new _Player Activity_ setting under _Players & Balance_ to set how long a player can go without doing anything before SLM counts them as idle.

   The AFK Kicker follows SLM's idle rule on its idle gamemodes, so it no longer kicks an inactive player who is in a squad
   or in a vehicle there. The kicker's `idleWindow` setting still decides how long a player stays idle before the kicker
   acts. Plugins can read
   the same rule from `slm/systems/player-activity` (plugin API 0.12).

   After the upgrade, SLM counts the players of every past match in the background, newest first, for the chart's day and
   week ranges. Until a match is counted, the chart notes how many in its range are still missing.

- **Changed:** Plugins can only be installed and refreshed over `https://`. SLM also refuses to install a plugin whose id is already installed from another url, and uninstalling a plugin now leaves it stopped if it is installed again.

   A plugin installed from an `http://` url can no longer be refreshed. Uninstall it and install it again from its
   `https://` url.

- **Changed:** SLM's memory use no longer grows with uptime. Several in-memory buffers and open browser connections kept everything they had ever handled until a restart.

   The `RCON PACKET` and `emitted event` log lines are logged at `debug` instead of `info`, so production logs at the default level are much smaller.

   SLM looks up a Discord user who has left your guild at most once every 10 minutes, so the warning for that lookup appears far less often. Editing or reordering Discord roles no longer makes SLM recheck every signed-in user's permissions.

   Background BattleMetrics refreshes use at most 45 of the 60 requests a minute that BattleMetrics allows, so requests made by admins are not held behind them.

   The upgrade drops six database indexes that no query reads and adds one for weapon filters on the history page. Expect the migration to take about half a second per million recorded events.

- **Changed:** SLM's web interface sends every action over one connection to the server. SLM now refuses that connection when a page on another site opens it, since that page could otherwise act as whoever was signed in. The session cookie is now `SameSite=Lax`, and `Secure` when `ORIGIN` starts with `https://`.

   A deployment behind a reverse proxy needs `ORIGIN` set to the url that browsers open, or the proxy must pass the `Host`
   header through unchanged. Otherwise the web interface cannot connect.

- **Removed:** The _RCON Cache TTL_ server settings are removed. SLM polls each game server at the old defaults: the current and next layer every 5 seconds, server info every 10 seconds and the roster every 5 seconds.

   The upgrade deletes the stored values of these settings and any comments on them. A role's server settings grant that named these settings alongside others keeps the others. A grant that named only these settings becomes a read grant on the same servers, so the role can still view the settings of those servers.

- **Fixed:** An admin list whose source cannot be read no longer takes admin status away from everyone on it. SLM keeps the list from its last successful read and logs a warning each time a read fails.

   A remote source that answers with an HTTP error now counts as a failed read, not as an empty list. A list that has not been read successfully since SLM started still grants nothing.

- **Fixed:** A top bar colour written to carry markup could run script for anyone who opened SLM's icon in their browser. SLM now draws the icon only from a colour it can read, and serves the icon so that it cannot run script.
- **Fixed:** A log line that SLM cannot parse no longer stops SLM reading the server's log. Before, events stopped appearing until SLM was restarted.

   Busy moments no longer stall SLM. A burst of a thousand kills or chat messages, a warn to every player, or a map change held up the rest of SLM for up to a second. Each now holds SLM up for a few tens of milliseconds at most.

- **Fixed:** Several security fixes:

   - SLM refuses to be shown inside a frame on another site, which could trick a signed-in admin into clicking its
     controls.
   - A queue editor can no longer send the queue operations SLM reserves for itself, which skipped the edit window and the
     pool and installed-mods checks.
   - The plugin list hides the query of an install url, where a token can be kept, and shows a plugin's error only to
     users who can manage plugins.
   - An open plugin stream stops for a user who loses the permission the plugin requires.
   - SLM refuses to install a plugin whose id is too alike to an installed plugin's for their database tables to be kept
     apart, such as `hello` beside `hello-x`.
   - A server join link must open Steam.

- **Fixed:** The server no longer keeps memory for every browser connection it has ever accepted. Each page load used to cost about 9 KB for the life of the process, so a browser stuck reloading grew the server by up to 50 MB an hour.
- **Fixed:** A user allowed to edit any one server setting could grant themselves every permission, including plugin installation. SLM now rejects the settings edits that made this possible. Upgrade promptly: the default managers role can edit server settings.
- **Fixed:** A user allowed to edit the permissions config or the admin lists could grant themselves any permission. SLM now refuses a save that would grant a permission the user saving it does not hold.

   The raw settings editor no longer lets a user without `server-settings:write-sensitive` replace a server's connection
   details while that server's stored settings are invalid.

- **Fixed:** A role's server settings grant that is limited to certain settings no longer widens to every setting when an upgrade removes all of the settings it named. The grant now lets the role view those servers' settings and edit none of them.
