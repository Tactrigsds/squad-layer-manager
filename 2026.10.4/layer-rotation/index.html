Setup guide/Configuring

Layer rotation

These settings decide what SLM plays next: the next layer, the repeat rules, generated votes, saved rotations, and how SLM picks layers at random.

Next layersource

The Next Layer tab holds two settings, both off by default. They decide how SLM reacts when the server's next layer changes underneath it.

Override the next layer when it is set outside SLM covers the case where something other than SLM sets the next layer, such as an in-game admin or another RCON tool. On, SLM sets it straight back to the next layer in the queue. Off, SLM adopts the change instead, and puts that layer at the front of the queue.

Warn admins when the next layer changes sends every in-game admin the new next layer whenever it changes. A change SLM overrides is not announced, so turning both on warns admins only about changes SLM accepted.

Generated and automatic votessource

Use the Generation & Votes tab to set whether SLM generates votes when the queue runs out, and when votes start.

With Generate votes on, SLM generates a vote between 3 layers instead of a single layer when the queue runs out. Each choice is on a different map. Use Vote Display Options to choose the parts of each layer that players see when a generated vote starts.

With Start votes automatically on, SLM starts the vote at the front of the queue once the match has run for Delay into the match, 20 minutes by default. Write the delay as a number and a unit, such as 90s, 20m or 1h. Turn the setting off to leave every vote for an admin to start.

Disabling SLM updatessource

SLM normally writes the next layer to the server over RCON. Use Disable SLM Updates, in the Server Actions menu, to stop SLM writing the next layer. The queue still runs and tracks what is played. SLM never sets the map itself, and stops sending the recurring reminders and announcements that describe the queue as the rotation. Disable updates to run SLM alongside something else that owns the rotation.

While updates are off, the queue panel carries an SLM Updates Disabled alert naming who turned them off. Use Re-enable SLM Updates to turn them back on. Both need squad-server:disable-slm-updates.

SLM also stands down on its own when Squad's built-in vote is deciding the next layer, or when it infers that voting was turned on with AdminEnableVoting 1. It reports that voting is enabled, and stops updating the next layer until someone turns updates back on. Turning them back on disables voting.

Repeat rulessource

A repeat rule sets how soon a map, layer or faction may be played again, counting across both the queue and the recent match history. Each rule covers one attribute.

Repeat rules are kept in repeat rulesets. A repeat ruleset is a named list of repeat rules that several servers and rotations can share. Each server uses one repeat ruleset, and a new server gets a repeat ruleset of its own, named after the server.

To change a server's repeat rules:

  1. Open the Repeat Rules tab of the pool configuration window.
  2. Pick a repeat ruleset under Repeat ruleset, or keep the one shown.
  3. Edit the rules.
  4. Press Save Changes.

Save Changes saves the rules into the repeat ruleset, so every server using that repeat ruleset gets the new rules.

Use New repeat ruleset, beside the picker, to create a repeat ruleset. It starts with a copy of the rules of the repeat ruleset picked under Copy rules from, which is the one shown unless another is picked, or with the default repeat rules. The server switches to the new repeat ruleset once Save Changes is pressed. Use the pencil beside the picker to rename the repeat ruleset shown. The settings page lists every repeat ruleset under Repeat Rulesets. A repeat ruleset can only be deleted there, and only while no server or rotation uses it.

These are the rules a new server's repeat ruleset starts with:

They treat a layer as a repeat when it reuses:

  • its Map within 4 matches
  • its Layer, which is the map, gamemode and version together, within 7 matches
  • its Faction, on the same side, within 3 matches

A rule on a team-specific attribute such as Faction or Unit reads that side's own history, not both. One side can still play a faction the other side played recently.

Use Target Values to narrow a rule to named values:

That rule covers Skorpo alone, over 10 matches. A Within of 0 turns a rule off.

A rule always hides its repeats behind the layer table's Hide Repeats. Options decides what else it does:

  • Indicate marks a layer that breaks the rule wherever it is shown: the repeat icon on the queue item and in the layer table, and the underline on the field that repeats.
  • Warn warns the editor before saving a layer that breaks the rule, and warns in-game admins when one is about to be played.
  • Autogen applies the rule when autogenerating layers as well. It is on for all three defaults, and off for the Skorpo rule above.
  • Cross-team pools both teams together, so a value one team played counts as a repeat when the other team plays it. Only a rule on a team-specific attribute can take it.

A rule is named after its attribute, unless Add label gives it a name of its own.

A seeding or training layer never breaks a repeat rule. A repeat rule looks back only as far as the most recent seeding or training layer, whether played or queued. A vote ends the lookback the same way only when every choice is a seeding or training layer.

Fixing repeatssource

While editing the queue, use Fix Repeats (the wand icon) to clear repeat warnings automatically. SLM reorders the queue and swaps layers' teams to clear as many warnings as possible, with as few changes as possible. Moving a layer one place and swapping a layer's teams each count as one change. SLM never swaps the teams of:

  • an Invasion, Destruction or Insurgency layer
  • a layer whose swapped matchup falls outside the pool
  • a layer with a tag that has Prevent swaps turned on

A layer that another admin is editing stays where it is. The changes stay in the draft until the queue is saved.

A repeat rule checks a layer against every choice of an earlier vote that has not taken place yet, because any of those choices could still be played. Once the vote picks a winner, or ends with too few votes, the rule checks only the layer the vote settled on. Aborting a vote puts all of its choices back in play.

Generated votessource

When the queue runs out of layers, SLM generates a single layer by default. Switch on Generate votes, in the Generation & Votes tab of the pool configuration window, to have SLM generate a vote between 3 layers instead.

Each choice of a generated vote is on a different map. SLM draws the choices under the pool filter, the Constrain generated pool for filters and the repeat rules, the same as a single generated layer. When a layer request is pending, SLM generates the requested layer on its own. When the repeat rules leave fewer than 2 maps, SLM generates a single layer.

Vote Display Options sets which parts of each choice players see when a generated vote starts. The map is always shown, because the map is the one part the choices are certain to differ by.

Undoing editssource

Use Undo and Redo in the queue's header, or Ctrl+Z and Ctrl+Y (⌘Z and ⇧⌘Z on a Mac), to step back and forward through your own edits to the queue. A saved rotation's editor provides the same buttons and keys. Click in an editor before pressing the keys, so the keys reach that editor. Inside a text field, Ctrl+Z and Ctrl+Y undo and redo the typing instead.

An undo takes back only your own edits. Another admin editing the queue at the same time keeps their edits, unless that admin changed the same layer after you did. After a layer is deleted, the queue is cleared or the queue's edits are discarded, SLM shows a message with an Undo button. An edit can still be undone after a save. The undo is then a new change that needs saving. Once another admin discards the queue's edits, there is nothing left to undo.

Saved rotationssource

Creating a rotation needs rotations:create. Whoever created a rotation can edit it, along with the users and roles added to it as contributors. rotations:write-all allows editing every rotation. Rotation tags, which group rotations on the Rotations page, are defined on the settings page under Rotation tags.

A note on an item added from a saved rotation shows a rotation icon in place of an author. Only an admin with queue:manage-all-notes can change such a note.

Rotation filessource

The toggle beside a rotation's Layers heading switches between Builder, which shows the layers as a list, and Text and YAML, which show them as plain text or YAML. The text holds the layers alone, without the rotation's name, description, rotation tags or repeat ruleset. Both formats write a layer as the line SLM sends with AdminSetNextLayer, so a layer line copied from one format pastes into the other.

# Opening layer. Keep it light while the server fills.
- Gorodok_RAAS_v1 USA+Motorized RGF+Armored
- layer: Narva_AAS_v2 BAF+CombinedArms VDV+AirAssault
  tags: [Event Night]
- vote:
     - GooseBay_RAAS_v2 CRF+CombinedArms AFU+LightInfantry
     - Mutaha_TC_v1 TLF+Armored ADF+Mechanized
  display: [map, factions]
  duration: 3m

In YAML, each # line directly above a layer or a vote choice is a note on it. Tags are written by label. A vote's first choice is its default. display sets what the vote shows players, from map, gamemode, layer, factions and units, and duration sets how long the vote runs. A vote without them uses the server's vote settings.

Plain text holds one layer per line, with # lines as notes on the next layer. A # TAGS: line names the next layer's tags by label, separated by ,. A vote starts with a # VOTE: line, which takes the same display and duration settings, separated by ;. The vote's choices follow it, indented, and the vote ends at the next line that is not indented.

# Opening layer. Keep it light while the server fills.
Gorodok_RAAS_v1 USA+Motorized RGF+Armored
# TAGS: Event Night
Narva_AAS_v2 BAF+CombinedArms VDV+AirAssault
# VOTE: display map, factions; duration 3m
  GooseBay_RAAS_v2 CRF+CombinedArms AFU+LightInfantry
  Mutaha_TC_v1 TLF+Armored ADF+Mechanized

The text can be edited once Start Editing is pressed. A change applies to the rotation's layers when typing pauses. SLM names every line it cannot read, and holds the change back until each one is fixed. A tag label that matches no tag also holds the change back, until the label is created as a new tag, dropped, or mapped onto an existing tag. While a change is held back, the view cannot be switched.

Use Open File..., or drop a .yaml, .cfg or .txt file onto a rotation's layers, to add the file's layers. Pick Add to start or Add to end to put them before or after the rotation's layers, or Replace to replace the rotation's layers with them. A rotation with no layers takes the file's layers without asking. The result is shown as text in the file's format, so any line SLM cannot read is listed there.

Use Copy and Download to take a rotation's layers out as text. In the Builder, each one asks for plain text or YAML. In Text and YAML, Copy and Download use the text on screen. Plain text downloads as a .cfg file.

Add Rotation on the queue reads the same formats on its Paste tab.

Randomizationsource

Layer Generation Weights controls how SLM picks layers at random. It covers layer generation, which runs when the queue runs out of layers, vote generation, and the layer table's random sort.

Generation walks down a configurable pick order of layer columns and matchups:

At each step it draws one value at random, using the weights configured for that column, and the draw narrows the pool the next step draws from:

An unlisted value weighs 0.1. Matchups are unordered, so [ADF, PLA] and [PLA, ADF] are one entry.

Generation keeps going down the pick order until one layer remains, or until the pick order runs out, in which case it picks one of the remaining layers at random.

The weights are relative, not probabilities. SLM normalizes them against the values actually available at pick time, and a value with no layers left is never picked. Your background filtering and the values already picked both narrow what remains, so configured weights do not map cleanly onto the resulting distributions.
