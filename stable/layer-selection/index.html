Features

Layer selection

SLM manages the layer rotation of one or more Squad servers. Admins work from a web app that signs in with Discord, and from in-game commands. To install SLM, see Installing. To learn SLM by using it, see Learning SLM.

The layer queuesource

The queue holds upcoming layers for the server, as a list of queue items. A queue item is either a single layer, or a vote between several layers. When a queue item reaches the top, SLM sets the queue item's layer as the server's next layer. For a vote, that layer is the vote's default choice until the vote ends, and the winning choice after. When the queue runs out, SLM generates a layer from your layer pool, the set of layers your server may play, and marks the generated layer with a dice icon. Filters and the layer pool describes the pool below.

Several admins can edit the queue at once, and each one sees who else is editing. Layers can be added one at a time, as a generated vote, or as a whole rotation, pasted in or picked from the saved rotations. Queue items can carry colour-coded tags and freeform notes.

The layer selection dialogsource

Use the layer selection dialog to search the full layer catalog for layers to add to the queue. Filters narrow the catalog, along with constraints on map, gamemode, factions, units and vehicles. The results can be shuffled, weighted toward preferable layers. Each layer is marked when it falls outside your pool or would break a repeat rule. A summary of the results lists the values each column holds and how many layers each filter matches or removes. The selected layers go into the queue as separate queue items or as one vote.

SLM works on a phone, and can be installed to your homescreen. See Can SLM be installed as an app?.

Filters and the layer poolsource

The base game offers about 730,000 layers, counting every map, gamemode, faction and unit combination, and mods add more. A filter is a named expression that picks a subset of them out, such as "no mechanized units on hilly maps". A filter can reference other filters. Filters can be edited in a visual builder or as YAML text.

Filters decide which layers admins can select by default and which layers SLM generates when the queue is empty. A filter can also mark the layers it matches with an emoji, as a category. See Layer pool and filters.

Repeat rulessource

A repeat rule defines how soon a map, layer, faction or unit may be played again, counting both the queue and the recent match history. The defaults catch the same map within 4 matches, the same layer within 7, and the same faction on the same side within 3. A rule can be narrowed to named values, such as Skorpo alone over 10 matches.

SLM marks each layer that breaks a repeat rule with , and underlines the repeated value in pink on both the marked layer and the earlier layer it repeats.

Use Fix Repeats to clear repeat warnings automatically. SLM reorders the queue and swaps layers' teams to clear as many warnings as possible, with as few changes as possible. See Fixing repeats.

Autogenerationsource

When the queue runs out, SLM generates the next layer from your pool. A generated layer obeys the pool filter, the filters set to constrain generation, and the repeat rules marked Autogen. Configurable weights make chosen maps, gamemodes or factions come up more or less often. When a layer request is pending, SLM generates the requested layer. SLM can generate a vote between 3 layers, each on a different map, in place of a single layer.

See Generated and automatic votes and Randomization.

Saved rotationssource

A rotation is a saved, ordered list of layers and votes, with their tags and notes. Rotations are kept on the Rotations page, where they can be searched, tagged, cloned and archived.

A rotation is edited the same way as the queue, and several admins can edit one at once. Each rotation follows a repeat ruleset, and the editor marks every layer that breaks one of the ruleset's rules. A rotation's layers can also be edited, copied and downloaded as YAML or plain text. Rotation files describes both formats.

Use Add Rotation on the queue to add a saved rotation to any server's queue in one step, or to paste one in. SLM tags each added item with the rotation's name.

Layer details and scoressource

Each layer shows a balance score and an asymmetry score, and compares its two teams on anti-infantry, armor, logistics and transportation. The scores are heuristics for how fair a matchup is likely to be. They come from a system created by community member ZERO, and refined through feedback on the TacTrig server. A custom layer dataset can replace the scores. See Building custom layer data. The current scores predate recent game changes. A revised scoring system is in progress.

Votessource

A vote lets players choose the next layer from several choices. Use the Generate Vote dialog to generate each choice from the pool, under optional constraints such as a different map for every choice. A choice can be edited or regenerated on its own.

A vote starts from the dashboard, in game with /startvote, or by itself partway into a match. Players vote by typing a choice's number in chat, and SLM broadcasts the choices and reminders to the server. An internal vote polls only the admins.

Each vote sets its own duration, and which parts of a layer the choices spell out, such as the map, gamemode or factions.

Squad's in-game votingsource

SLM also works on a server that uses Squad's own in-game voting system. When an in-game vote starts, or SLM infers that voting was turned on with AdminEnableVoting 1, SLM stops setting the next layer, so SLM and the vote never fight over it. The server's dashboard shows that an in-game vote is deciding the next layer.

Layer requestssource

An admin can request a kind of layer instead of queuing a particular one. A request names any mix of map, gamemode, faction, unit or filter. /reqlayer fallu raas usa rgf requests Fallujah RAAS with USA against RGF. When the queue runs out of deliberately queued layers, SLM generates the next layer from the requests, and satisfies as many of them as it can at once. If one admin requests WPMC and another requests Narva, the generated layer can be WPMC on Narva.

Mod supportsource

SLM's layer catalog covers vanilla Squad and SuperMod. Resurgence and Galactic Contention are left out until each is updated for the current version of Squad. More mods can be added on request, as Layer data, Mods describes. Each layer's Collection column records whether the layer is vanilla (OWI) or which mod it comes from, so a filter can include or exclude a whole mod. Each server's settings name the mods that server has installed, and SLM never queues, generates or offers a layer from a mod the server lacks.

A custom layer dataset can replace the built-in one, with other mods, other scoring or extra columns. See Layer data and Building custom layer data.

A layer the catalog does not know can still be queued as raw text from the Add Layers dialog, in the format AdminSetNextLayer takes, such as Narva_RAAS_v1 RGF USMC.
