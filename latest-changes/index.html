Changelog/Releases

Latest changes

These changes are merged into main and will ship in the next release.

For userssource

  • Added: Filters that cannot be applied are marked wherever they are used, with the reason and a link to the failing condition.

    • The queue dashboard lists each filter of the server's configuration that cannot be applied, and what the configuration uses it for.
    • A queued layer is marked when a filter could not be checked against it.
    • The layer table names the filters that cannot be applied to its results, beside the result count. The summary view marks each of those filters.
    • The vote generation dialog names the filters its choices were generated without. The Fix Repeats message names them too.
    • A layer request whose own filter cannot be applied is marked in the layer requests panel.
    • The filter list, the applied filters and the filter pickers mark each filter that cannot be applied.
    • The filter editor marks each condition that cannot be applied and lists the problems above the filter. Select a problem to jump to its condition. A problem in a referenced filter links to the failing condition in that filter.
    • A filter that cannot be applied can still be saved, with a warning that counts its problems.

  • Added: The history page can search votes by kind (layer or simple), outcome, voters (public or internal), and the text of a choice or of the winner. Add them from the Vote group under "+ Filter", or as columns in the advanced editor.

    Votes recorded before this update can be searched by kind and outcome only.

  • Added: On a phone, the back gesture closes the open dialog, menu or window instead of leaving the page.

    With several open, each back press closes the top one.

  • Added: /reqlayer and /vote take --filters (-f) to choose the filters a request or vote uses. The filters named replace the server's layer request filters for /reqlayer, and the pool filter for /vote. Separate the filters with commas, put ! before one to invert it, or give none to use no filters: /reqlayer narva -f mainpool,!jensens. The repeat rules still apply to /vote.

    A filter can be named by part of its name or by its id, in --filters and among the words of /reqlayer and /vote. When a name matches no filter or several, SLM lists the filters it could mean. Reply with a number to pick one. Every mistyped word and filter in a /reqlayer or /vote is asked about in the same exchange, one question after another, and the answers can be given together: 1 1.

    Only admins who can edit the queue can choose the filters of a /reqlayer request.

  • Added: The new Scheduled Commands plugin runs RCON commands on your servers on a schedule. A task can run on an interval, at set times from a cron pattern, a set time after each match starts, or a set time after each match ends.

    Each task is listed under the plugin on the settings page with its next run and its last result. Click Run now to run a task straight away. Commands can include variables such as {{layer}}, {{nextLayer}}, {{server}} and {{players}}, filled in each time the task runs. Each command appears in the server's activity feed.

  • Added: The activity feed shows players getting into a vehicle, moving to another seat, and getting out. Find them under the All and Vehicles & Deployables filters, and in history.

    Each row names the vehicle and the seat number. Hover over the seat to see which turret, periscope or passenger seat it is.

  • Added: Admins can generate a vote from game chat with /vote, and run a vote between text choices with /simplevote.

    /vote narva skorpo goro generates a vote with one layer from the pool for each map named, and puts the vote first in the queue. The choices can also all be layers, gamemodes or sizes, and a filter name applies to every choice. When the pool has no layer for a choice, SLM names that choice and queues nothing.

    A vote's choices can show players a text of their own in place of the layer's name. Type it after a colon in /vote, with underscores for spaces: /vote narva:Night_ops skorpo. The vote's display options set the same texts from the dashboard.

    /simplevote yes, no, not sure starts a vote that leaves the queue as it is. Commas separate the choices. Without a comma, each word is a choice. --internal (-i) has only the admins vote, in admin chat, and --duration 2m (-d) sets how long the vote runs. /startvote takes the same two options for the vote at the head of the queue. A simple vote can also be started from the activity panel's chat box, which sets the same two options.

    Every vote, layer or simple, shows its tally and countdown in a box at the top of the activity feed, with the controls to end or abort it. The queue no longer shows a running vote's tally.

  • Changed: The Scoreline chart is now called Scores and plots tickets by default. The Population chart's Teams view plots how many more players one team had than the other.

    The Population chart's Stats for a single match cover the round. They show the player count at the round's start and end, and the joins and leaves during the round.

    The scoreboard plugin's Discord post includes a kill lead chart, between the kills and tickets charts.

  • Changed: The charts get a screen of their own on a phone and in a narrow window. The Charts panel can also show every chart at once.

    In a window too narrow for two columns, the dashboard now switches between Layers & Teams, Server Activity and Charts. A phone gets a Charts tab. On a wider window, the button beside the Charts panel's title switches between one chart at a time and every chart at once.

  • Changed: Filters and rotations are created and edited the same way. A rotation's name, description and other details are edited in the Edit Details dialog, opened from the pencil beside the name, as a filter's are.

    New Rotation now opens a page for the new rotation, where its layers can be added before it is created. The New Rotation dialog opens with the page, and can be closed and opened again from the pencil beside the name. Create saves the rotation with its layers. New Filter works the same way. A new rotation no longer offers to copy another rotation: use Clone on that rotation instead.

    A rotation's description is shown as markdown, like a filter's. On a filter, Apply adds the changed details to the filter's draft, and Save on the filter page saves them.

  • Changed: The activity feed folds repeated combat events from one player into one expandable row. A gunner's run of hits on one vehicle, a multi-kill with one weapon, and several deployables destroyed with one weapon each show as one row.

    The row sums up the run, such as "hit BTR-80 12 times for 340". Expand it to see each event. Events join a row while they keep arriving less than 5 seconds apart. Warns that share their text and sender now fold the same way, and a folded warn row now updates its count as more warns arrive.

  • Changed: Conditions in the filter editor are added and changed from one searchable menu. The menu sorts conditions into Block, Layer, Faction, Vehicle and Scores tabs, and opens on the tab of the condition being changed.

    Any condition can be changed into any other kind. A condition keeps what still applies after the change: a block keeps its conditions, a matchup keeps its teams, and a faction or unit condition passes its values to a matchup and back. A condition that becomes a block is kept inside the new block.

    Included in filter, excluded from filter, allow matchups and disallow matchups are separate entries in the menu. A matchup starts with only its faction and unit fields. Use + dimension to add alliance or vehicle fields.

    A condition's collapsed row lists every value it matches, and wraps onto more lines when the values do not fit. Select layers conditions list their layers instead of a count. The save, clone and delete buttons sit beside the filter's description, so the conditions use the full width of the page.

  • Changed: The activity feed and history show every hit on a FOB radio, in place of one line when an attack starts. A player's run of hits on one radio is grouped into one line with the number of hits and the total damage, as hits on a vehicle are. Taking a radio down to minimum health still gets a line of its own.

  • Changed: A filter that cannot be applied no longer stops SLM from generating a layer. A filter cannot be applied when it names a column or value the current layer data does not have, or applies a filter that was deleted.

    SLM now generates the next layer or vote from your server's other filters. SLM warns the admins in game, naming each filter it left out, and the activity feed records the generated layer with those filters. Before, SLM queued a fixed default layer instead. The next-layer warn that admins see also names each filter the next layer could not be checked against.

    A layer request filter that cannot be applied is left out of new layer requests, and the reply names it. A request that applies such a filter itself is refused with a message saying the filter cannot be applied, instead of "No layers in the current pool match this request".

  • Changed: In game, /help from an in-game admin replies with a link to the commands page and the names of the command sections, instead of listing the quick reference commands. Other players get the commands they can run, five per page. /help 2 shows the second page. /help <section> still lists a section's commands.

  • Changed: The filter, rotation and settings text editors list every problem with its line, and underline it in the text.

    • Click a problem to move the cursor to it. The copy button copies the whole list.
    • The editors can be expanded to fill the screen. Esc returns to the page.
    • A rotation's YAML view lists its problems in a column beside the text, and takes the full width of the page.
    • A rotation's text can be typed into straight away. Typing starts editing.
    • A rotation with problems in its text cannot be saved or switched back to the builder until they are fixed.
    • Selected text in the editors is easier to see.
    • In the rotation builder, Open File, Copy and Download are in the ⋯ menu.

  • Fixed: Cancelling a vote's automatic start stops the vote from starting.

  • Fixed: The activity feed and history show every warn sent on your server, including warns sent by other admin tools. Some of those warns were missing before.

  • Fixed: Dropdowns and menus open and close faster, most of all on the settings page, where a dropdown took about 300 ms to open.

  • Fixed: SLM puts the server's next layer back in line with the queue when the server changes it without logging the change, and warns in-game admins when the next layer leaves the queue.

    With Override the next layer when it is set outside SLM on, SLM sets the queue's next layer back and warns every admin, naming the admin who changed it when the server log does. With the setting off, SLM adopts the server's layer into the queue. Admins are also warned when a match starts on a layer the server picked itself. A next layer the server refuses is retried.

  • Fixed: Comments on a plugin's settings are saved. Before, editing a plugin setting's comment did not bring up the Save button, and saving the plugin's settings dropped the comment.

    The Save dialog lists the first comment added to a settings section, and the last comment removed from one, under the setting the comment annotates. Before, the dialog listed it as a change to every comment at once.

  • Fixed: The repeat ruleset picker no longer warns that a ruleset does not exist when the ruleset does. The warning could appear after a rotation or another server's settings had been open earlier in the same session.

  • Fixed: A vote started again after it was aborted shows as running on the dashboard, rather than as not yet started until the page is reloaded.

  • Fixed: Saved teamswaps no longer fail with a "NOT NULL constraint failed" error when they run at the start of a new match, are swapped now, or are cleared.

    At the start of a new match, the players were still swapped, but the toast reported the swap as failed.

  • Fixed: The warning about unsaved edits now appears only when leaving the page.

    Switching tabs on the server dashboard, or moving between sections of the settings page, no longer asks to discard edits.

Smaller fixes and tweaks

  • Added: Snow falls across SLM in December, and your avatar wears a santa hat. Turn off Christmas Cheer in the account menu to hide both.

  • Added: The layer table's Summary tab shows how many results field each vehicle and vehicle type, for each team. A layer counts once toward every vehicle its team fields, so the counts in a vehicle card add up to more than the number of results. Hover over a value in a Summary card to see its full name when the card cuts it off.

  • Added: The server console, player details and squad details windows can be maximized to fill the screen. Press the maximize button again to restore the window to its previous size and position.

    The activity feeds in the player details and squad details windows can be searched, like the server activity panel and the server console. Press the search button at the top right of a feed, or Ctrl+F after clicking into the feed.

    Ctrl+F after clicking into the server console window now opens the console's search instead of the browser's.

  • Changed: The filters bar above the layer list now scrolls through all of its filters, including the layer pool and its default filters, and stretches to the full width of the dialog. The scrollbar no longer covers the filter checkboxes.

  • Changed: In-game command usage and the command help on the settings page name the argument that takes a message shorthand <shorthand|message> instead of <reason|message>, matching the Message Shorthands settings.

  • Changed: Dropdowns with long lists open faster, such as the vehicle pickers in Add Layers.

  • Changed: A filter's References section lists only what references the filter directly. A layer pool or plugin that reaches the filter through another filter is no longer listed.

  • Changed: The scoreboard's Squad Kills leaderboard lists each squad by its number, the player who created it and its faction, such as "Squad 3 (grey, USMC)", in place of the squad's name.

    The FOB/HAB Destroyer leaderboard is renamed FOB Destroyer. It ranks players by the damage they dealt to enemy FOB radios, and no longer counts HABs.

  • Changed: On the settings page, a setting's controls show at the right of its name when the pointer is over the setting. The default value moved into the tooltip of the reset-to-default button, and the reset-to-saved tooltip shows the saved value.

    Use the link button beside a setting to copy a link to it. SLM confirms every copy with a one-line message, and warns when a copy fails.

    When an editor such as the roles editor is wider than the settings page, the page scrolls sideways instead of cutting the editor off.

  • Changed: Switch requests and Timeouts above the teams tables moved into the More menu (⋯). The menu button shows a count while either list has entries.

    When the controls above the teams tables run out of room, Show Spoilers and then Admins Only move into the More menu instead of wrapping onto a second line.

  • Fixed: A layer that is not tied to a match shows its teams in the layer's own order, without (1)/(2) or (A)/(B) markers. That covers layers picked into a filter, the layer history window, and activity feed lines about queue edits, votes and fulfilled requests. Feed lines about a next layer set on the server mark its teams with the sides of the match it is set for, instead of sides that were sometimes wrong.

  • Fixed: The links menu shows each site's icon for more sites, including BattleMetrics, MySquadStats, SquadCalc and the SLM docs. Dark icons such as GitHub's stay visible on the dark theme, and the icons no longer pop in after the menu opens.

  • Fixed: A new tab no longer opens already editing. A tab opened within a few seconds of another of your tabs losing its connection took over that tab's editing session, such as an edit of the queue.

  • Fixed: Opening a dropdown closes the one already open. Before, two dropdowns could stay open side by side in the layer filters.

  • Fixed: When the RCON connection drops during a map change, the match feed no longer falls 15 seconds or more behind, and SLM sets the queued next layer once the connection returns.

  • Fixed: Opening a Select layers condition in the filter editor no longer opens the layer picker. The picker opens on its own only when the condition is added.

  • Fixed: The settings page responds faster to edits.

For operatorssource

  • Breaking: A plugin of your own that calls slm/systems/layer-queries must handle filters that cannot be applied through problems, and its manifest must declare plugin API 0.23. query, componentValues, outOfPool and itemStatuses no longer return err:invalid-node. A constraint whose filter cannot be applied is left out of the query, and the result lists it in problems (statuses.problems for itemStatuses), so a query on that filter alone matches every layer. genVote returns err:invalid-choices in place of err:invalid-node, with the index of each choice whose own constraints cannot be applied. A layer in a query or genVote result holds null in constraints for each constraint the query left out or did not evaluate, where it used to hold false.

    Each error names the stored filter it is in and the path to the failing node. describeNodeValidationError in slm/models/filter writes one as a log line. The plugin guide's "Layer queries" section describes the new results. The tt-slm-plugins set ships an updated release alongside this one.

  • Added: Plugin API 0.22.2 lets a plugin time jobs from a match and derive its jobs from its config. afterMatchStart and afterMatchEnd in slm/plugin/schedule run a server job a set time after the server's match starts or ends. The server module's jobs export can be a function of the config, called again on each save, and a job's label and description name and describe it on the settings page. execute in slm/systems/squad-rcon runs a raw RCON command and records it in the audit log. Plugins built for 0.22.1 keep working.

  • Added: Plugin API 0.22.3 lets a plugin link to a rotation from outside SLM, such as in a Discord message. pageUrl in slm/systems/rotation returns the rotation page's address, built from ORIGIN. Plugins built for 0.22.2 keep working.

  • Changed: The help command now accepts public chat as well as admin chat. The upgrade opens it to public chat where its allowed chats were admin chat only. To keep it admin-only, turn public chat back off for the help command on the settings page after upgrading.

  • Changed: The plugin API is version 0.24, and plugins can start votes. A plugin built for 0.23 does not load until its apiVersion is raised to ^0.24.

    slm/systems/vote starts the layer vote of a queue item, starts a simple vote between text choices, and follows the simple vote's tally to its result. The version moved because a vote's config gained the text shown for each choice, and the per-server ctx gained the vote state.

  • Fixed: A server agent whose connection was dropped by a proxy reconnects within a few seconds. SLM used to reject the reconnecting agent as a duplicate for up to 30 seconds, and RCON and log streaming stopped for that time.

Smaller fixes and tweaks

  • Added: pnpm plugin:pack warns about each plugin config field that the settings page would show as a raw JSON editor.

    A plugin config field typed string | number, nullable or not, now renders as a text input. A filter named in a nullable object, a union branch or a record entry of a plugin's config now counts as a reference to that filter.

  • Added: With telemetry on, SLM exports its own CPU time and memory, and the bundled Grafana overview dashboard shows them in a new Process row.

    The metrics are process.cpu.time and process.memory.usage, the container's memory split into anonymous memory and page cache (slm.cgroup.memory.usage), and the memory held by each worker thread's heap and by the layer engine. Use them to choose the CPU and RAM to give SLM.

  • Fixed: The Docker image runs Node.js 24.22.2, which includes fixes to V8 and to streams.
