Changelog/Releases

Latest changes

These changes are merged into main and will ship in the next release.

For userssource

  • Added: Ctrl+Enter (Cmd+Enter on a Mac) submits the focused dialog, window or popover, then closes it. Buttons that respond to Ctrl+Enter show the shortcut.

    On the history page, Ctrl+Enter runs the query. In a picker that selects several options, Ctrl+Enter toggles the highlighted option, applies the selection, then closes the picker. It no longer runs the history query behind the picker as well.

  • Added: SLM can generate a vote when the queue runs out. Switch on Generate votes in the Generation tab of Pool Configuration.

    A generated vote offers 3 layers, each on a different map, chosen under the pool's filters and repeat rules. Use Vote Display Options in the same tab to choose what players see for each choice. The map is always shown. When a layer request is pending, SLM still generates the requested layer on its own. When the repeat rules leave fewer than 2 maps, SLM generates a single layer instead.

  • Added: History can show times in UTC, in a server's time zone, or in any IANA time zone.

    Pick one in the new Time zone field. The From and To bounds are entered in the same zone, and saved queries and shared links keep it. The default is still the browser's time zone, and event times now follow it. Before this change they used the SLM host's time zone, while their tooltips used the browser's.

    Two new settings set time zones. timeZone, per server, is UTC by default. defaultTimeZone, global, sets the zone of history links quoted into Discord and of history results a script fetches as text or CSV, when the link or query sets none. By default it is the time zone of the server the events are from. The Discord reply now names the number of events and their time zone.

  • Added: Rotations can be saved and added to a server's queue in one go. A rotation is an ordered list of layers and votes, with their tags and notes, kept on the new Rotations page.

    Use the Rotations page to search, tag, clone, archive and delete rotations. A rotation's layers are edited the same way as the queue's, and several admins can edit one at once. Each rotation uses a repeat ruleset, and the editor marks layers that break its repeat rules. A rotation's layers can also be edited as YAML or plain text, and copied or downloaded in either format.

    Add Rotation replaces Paste Rotation on the queue. Paste layers on the Paste tab, or pick a saved rotation on the Saved Rotation tab. Pick Replace to replace every layer in the queue. Items added from a saved rotation carry a tag showing the rotation's name.

  • Added: Each team's tickets update live while a match is in progress, in the match history and on the Scoreline chart. Pick Tickets above the Scoreline chart to plot both teams' tickets across the match. Use /tickets in admin chat to see each team's tickets and K/D in game.

    The current match's scoreline and tickets are spoilers now, hidden until Show Spoilers is on. Clicking any hidden value shows every spoiler at once, the teams panel's role, vehicle and K/W/D columns included. Spoilers show by themselves when a match ends, and hide again when the next match starts unless they were shown by hand.

    Matches played before this version show no ticket history.

  • Added: A filter can exempt layers from its miss indicator. An exempt layer does not show the filter's miss emoji or alert message, and SLM does not warn that it misses the filter.

    Set the exempt layers under Miss Indicator when editing a filter's details. Every filter, existing or new, starts out exempting seeding and training layers, so those layers no longer show a filter's miss emoji. SLM already skipped warnings for them.

  • Added: The server activity feed in the player details window can be expanded to fill the window. Use the expand button beside the feed's filter to switch between the feed and the full player details. The This match summary lays out its fields in a row instead of a grid, so it uses less of the window.

  • Added: Automatic vote starts can now be turned on or off, and their delay into the match set, from the Generation & Votes tab of the pool configuration window. The tab was called Generation.

  • Added: The player details window lists the usernames a player has gone by before. Click the history icon beside the username to see each name and the dates it was used.

    A player can also be found by a previous username in the history page's player search.

  • Added: Servers can share repeat rules. Repeat rules are kept in named repeat rulesets, and each server uses one.

    Pick a server's repeat ruleset on the Repeat Rules tab of the pool configuration window, or create or rename one there. Save Changes saves edited rules into the repeat ruleset, so every server using it gets them. A new server gets a repeat ruleset of its own, named after the server.

  • Added: Sandbox Controls can put players in in-game parties. Use the Party column to create a party, move a player into an existing one, or take them out of their party.

  • Added: SLM marks each server with a color. On the server dashboard, the bottom border of the navigation bar takes the color of the server, and the server switcher and server lists show each server in its own color.

    A new server gets a color that stands apart from the existing ones. Existing servers get one on upgrade. Change a server's color under Color in its settings.

  • Added: RCON commands can be run from the server console. Type a command into the box at the bottom of the RCON tab and press Enter. Press Up and Down in the box to step through earlier commands, as in a terminal.

    Running commands requires the new squad-server:write-console permission, which no role holds until an admin grants it. squad-server:view-console still grants reading the console only. Every command run from the console is recorded in the audit log and in the server's activity feed.

    The console no longer has an All tab. The RCON tab shows only commands run from the console until Show SLM requests or Show events is ticked.

  • Added: Teamswaps can counterbalance. With Counterbalance turned on in the swaps panel, SLM queues swaps from the other team whenever an admin queues or removes a swap, so that the teams end up the same size.

    Counterbalance swaps carry a scale icon and a dashed outline. A party is always swapped together, and SLM keeps the players it already picked for as long as the teams need them. If players joining, leaving or switching teams leave the saved swaps uneven, a 2 minute countdown appears in the swaps panel. When it ends, SLM re-picks the counterbalance swaps and records why in the activity feed. Re-pick now and Skip act on the countdown early. Swaps queued with an in-game command are not counterbalanced.

    Use the Teamswap Counterbalance server settings to choose which players are never picked, by group, kills, wounds or K/D, and which players are picked first. Remove a counterbalance swap to have SLM pick a different player.

  • Added: Edits to the queue, saved rotations and filters can be undone and redone.

    Use Undo and Redo beside the reset button, or Ctrl+Z and Ctrl+Y (⌘Z and ⇧⌘Z on a Mac). An undo takes back only your own edits, so other admins editing at the same time keep their edits. After a layer is deleted, the queue is cleared or edits are discarded, SLM shows a message with an Undo button. The reset buttons now show a circular arrow, and the curved arrows now mark undo and redo.

  • Added: The vehicle tables in layer details show each vehicle's ticket value: the tickets its team loses when the enemy destroys it.

    The value comes from the game's own vehicle rules. Vehicles in modded layers do not have a ticket value yet, and show a dash.

  • Added: Line wrapping can be turned off in the server console, the activity panel, the history page's events, and the activity feeds of the player and squad details windows. Use the wrap button beside the search button, or in the toolbar or header above the feed, to turn line wrapping on and off. With wrapping off, each entry stays on one line. In the console, long lines scroll sideways. In the feeds, a line too long for the panel is cut short.

  • Changed: The Filters page can search filters by name or description, narrow the list to one author, and sort it. The search is kept in the page's address, so a filtered view can be linked.

    Filters can be cloned from a filter card's menu or from the filter editor. Right-clicking a filter card opens the same menu.

  • Changed: Admin action reasons are now called message shorthands. Your existing shorthands, and the comments and permissions on them, carry over unchanged.

    The in-game command that lists them is now List Message Shorthands, and keeps its triggers. New installs also get the /shorthands trigger for it.

  • Changed: Repeat rules check a layer against every choice of an earlier vote that has not taken place yet.

    A vote that has not taken place could still play any of its choices, so a layer that repeats any one of them counts as a repeat. Once the vote picks a winner, or ends with too few votes and falls back to its first choice, only the layer the vote settled on counts. An aborted vote can be run again, so all of its choices count again.

  • Changed: Tutorials are split into chapters.

    A step card names its chapter and marks progress through that chapter, in place of the overall step count. The contents group steps by chapter, a card between chapters marks each one finished, and the Tutorials page can start a tutorial from any chapter.

  • Changed: Warn in the player, squad and selection menus opens a dialog, like Kick. Pick a message shorthand or choose Custom to type your own warning.

  • Fixed: In-game commands answer a player whose Steam account an admin linked to somebody who has never signed into SLM.

    SLM sent no reply to any command from such a player, and ran none of them.

  • Fixed: When someone deletes a filter, anyone else viewing that filter is returned to the Filters page, even with unsaved changes, since they can no longer be saved. A toast on the Filters page names who deleted the filter.

  • Fixed: The activity feed shows when a player dies of their wounds. Such a death used to read as a kill made with the victim's own kit.

  • Fixed: Generate Vote follows your server's repeat rules. Hide Repeats is on by default and keeps layers that break a repeat rule out of the choices. With Hide Repeats off, a choice that breaks a repeat rule shows the repeat indicator.

  • Fixed: The history page's Chat contains filter no longer fails with a server error when the text includes punctuation such as !, - or ".

    The filter matches its words as typed, next to each other and in order. NOT, AND and OR are searched for as ordinary words. A player name search of two characters that includes an emoji now finds the matching players.

  • Fixed: On the history page, the clear button beside a text or number filter, such as Match id or Chat contains, now empties the field. Clear All also empties those fields.

  • Fixed: Long broadcasts reach the game in full.

    A broadcast with a very long paragraph lost every line of that paragraph except the overlong ones. A long broadcast written in a non-Latin script, such as Cyrillic, failed to send at all.

  • Fixed: A player whose Epic account changed behind the same Steam account no longer stops SLM from following the roster.

    SLM kept the old link and refused the new one, so team changes, squad changes and new players went unrecorded on that server until the player left. The Steam account now moves to the player's new account.

  • Fixed: Plugin panels that show live data, such as the seed roller's panel on the server dashboard, appear instead of staying empty.

  • Fixed: Panels that plugins add to the server dashboard appear when the page first loads, rather than only after leaving the page and coming back.

  • Fixed: An installed plugin no longer breaks the phone layout. On the Activity tab, the recipient and event filter controls stay on one line above the message box again.

  • Fixed: A queued seeding or training layer ends a repeat rule's lookback, as a played one does.

    A layer queued after a seeding or training layer no longer counts as a repeat of anything before the seeding or training layer. Fix Repeats leaves queued seeding and training layers where they are. The layer table's Hide Repeats no longer hides seeding and training layers, and the layer table no longer marks them as repeats.

  • Fixed: The audit log shows the queue update that records a vote's result.

    When a choice other than the first won a vote, the queue update that applied the result was missing from the audit log. The update also dropped out of the activity feed once SLM restarted or the match ended. The upgrade restores the updates that are already recorded.

  • Fixed: The activity feed and history now record warns and kicks that SLM used to miss.

    A warn was missing when the player's in-game name had just changed, such as a clan tag appearing or disappearing, or a doubled space after the tag. A kick that no admin issued was missing too.

    A kick from SLM no longer counts as refused when the player takes a moment to leave the server. Before, the feed did not show who made such a kick, admins in game were not told about it, and the AFK kicker kicked more players than the queue needed.

Smaller fixes and tweaks

  • Added: Click a screenshot in the documentation to view it full screen. Scroll, pinch or click to zoom, and drag to pan. Press Escape, click beside the image or use the X to close the viewer. Each screenshot is captioned.

  • Added: The panels, row highlights, activity lines and styles that plugins add can be hidden with Hide Plugin UI in the user menu. Use the switch to check whether a problem on a page comes from a plugin.

  • Added: The history page's match results show each match's id. Click the Match ID header to sort by it.

    Click a match id in the match results, the event feed or a match's tooltip to copy it. A click on a match id in the event feed also pins the match's tooltip open.

  • Added: Recent layer searches can be recalled with the arrow keys. In the layer search box, press Down to move into the recent searches listed below the box, and Up to move back to the text being typed.

  • Added: Middle-click a picker to clear its selection. A picker that can be cleared this way shows "Middle-click: clear" on hover.

  • Added: Clicking an entry in the population chart's legend hides or shows it on the chart: active players, idle players, match starts and round ends.

    The options above the Teams Breakdown, Scoreline and Population charts are grouped into button sets, one per choice.

  • Added: The right-click menu for several selected players now offers Clear selection. The teams panel's reset button is disabled while there is nothing to reset.

  • Changed: Documentation versions are named like the image tags: latest, stable and release numbers such as 2026.10.1. Old links still open.

    The version menu lists the newest release once, as stable (2026.10.1). Each version opens on its own start page. On a phone, the version menu opens inside the navigation menu, where every version can be picked.

  • Changed: The Explore Layers button in the top bar shows a map icon.

  • Changed: The filter text editor gives the errors pane a smaller share of the width by default. Drag the divider between the editor and the errors pane to resize them, or double-click it to restore the default. The width is remembered in your browser.

  • Changed: Add Layers and Gen Vote open on the collection last picked in any layer picker, as Explore Layers already did.

    Explore Layers and the layer pickers on rotations also share their applied filters. A filter switched on in one stays on in the others until the page is reloaded. Editing an existing layer still opens with that layer's own defaults.

  • Changed: The match history's Outcome column is now named Scores. The row of the match in progress drops its "In progress" badge, so the row fits the column. The play icon beside the row marks the match in progress.

  • Changed: The button that confirms a dialog or saves a form is orange, so the main action on each screen stands out from the rest.

  • Changed: Keyboard shortcuts keep working while a menu is open. Undo and redo act on the queue, rotation or filter the menu was opened from.

    Ctrl+F opens a panel's own search while focus is in the panel, or while nothing has focus and the pointer is over the panel. Ctrl+C copies selected feed rows while the feed is the last thing clicked.

  • Changed: Warning notifications have a close button. Click it to dismiss a warning without acting on it.

  • Removed: Sandbox Controls no longer embeds the server console. Open the console from Server Actions -> Server Console.

  • Fixed: The Teams Breakdown chart shows Team A on the left when teams are displayed as A and B. Before, the chart put Team B on the left in every other match.

  • Fixed: A filter added as an extra filter no longer appears twice in a dialog where the server's layer pool already shows it. The filter stays in your extra filters, so dialogs that do not show it by default still list it.

  • Fixed: Hovering a layer name underlines the factions and units along with the map.

  • Fixed: Repeat warnings in the layer picker name the faction or unit that repeats. Before, a warning could name the faction or unit on the other team.

  • Fixed: Ticket counts and results in the Match History outcome column line up from row to row.

  • Fixed: Moving a vote in the queue while editing now marks its choices as moved too, not only the vote.

  • Fixed: On a phone, the pool configuration window fits on screen. Its tabs appear in their own row below the title, and each repeat rule appears as a card with a caption above each control.

  • Fixed: On a phone, the queue's editing controls fit on screen. Save appears where Start Editing was, with Reset beside it, and the tools for adding and changing layers appear in a row below.

  • Fixed: The activity feed in the player details window stays in place when older events load. Scrolling the feed afterwards no longer snaps back to where it was.

  • Fixed: An edit made in the pool configuration window while a save is in progress is kept. Before, the edit was discarded when the save finished, and Save Changes stayed disabled. Edits are also kept when another admin saves the same server's settings.

  • Fixed: Queue items no longer stay locked after the admin working on them moves on to another item or another browser tab.

    An admin can also start a second action on a queue item they are already working on.

  • Fixed: A toast can be clicked while a dialog is open. Clicking a toast leaves the dialog open.

  • Fixed: The layer queue tutorial no longer says SLM computes the layer scores. SLM includes scores that were generated elsewhere.

  • Fixed: A window such as player details can no longer be dragged so far off screen that its title bar is out of reach. The title bar stays on screen at full height and at least 100px wide, so the window can always be dragged back.

For operatorssource

  • Breaking: Plugins must be updated for plugin API 0.20, which changes what a layer id is. Update tt-slm-plugins along with SLM.

    SLM now stores a layer id as the layer's name and its two teams in the game's own words, such as Narva_RAAS_v1:USA+CombinedArms:RGF+CombinedArms. SLM rewrites the layer ids it stored before into this form: saved queues, layer requests, rotations and filters as it starts, and match history and the activity feed in the background a few minutes later. Links to a layer written with an old id still open that layer.

    An older SLM cannot read the rewritten ids. Back up the database before upgrading, so a rollback can restore it.

  • Breaking: The plugin API is version 0.13. A packed plugin that declares ^0.12 does not load until it is rebuilt against 0.13.

    The built-in plugins are already updated. For a plugin of your own, set apiVersion to ^0.13 in its manifest and repack it with pnpm plugin:pack. Changes since 0.12:

    • Filters gain missExemption, a filter node or null. Layers that match the node do not show the filter's miss indicator, and null exempts no layer. Filters.create exempts seeding and training layers when missExemption is left out.

  • Breaking: The plugin API is version 0.19. A plugin built for an earlier version does not load until its apiVersion is raised to ^0.19 and it is repacked with pnpm plugin:pack.

    The built-in plugins are already updated. Changes since 0.18:

    • The layer naming functions moved from slm/lib/display-helpers to slm/models/display-helpers. Change a plugin's imports to the new specifier. The functions are unchanged.

  • Breaking: The plugin API is version 0.16. A packed plugin that declares ^0.13 does not load until it is rebuilt against 0.16.

    The built-in plugins are already updated. For a plugin of your own, set apiVersion to ^0.16 in its manifest and repack it with pnpm plugin:pack. Changes since 0.13:

    • A note copied from a rotation has no author, and its fromRotation names the rotation. A plugin that reads note.author must handle a note without one.
    • A tag id can be from-rotation:<rotationId>, which names no configured tag. A plugin that looks tag ids up in the layer tags must handle one it does not find.
    • A new item passed to add may carry notes, but only notes with no author and a fromRotation.

  • Breaking: Repeat rules moved from each server's settings into repeat rulesets in the global settings.

    The upgrade migrates them automatically. Each server's queue.mainPool.repeatRules becomes a repeat ruleset under the global repeatRulesets setting, named after the server, and the server's settings point at it with queue.mainPool.repeatRulesetId. Tutorial servers share one slm-tutorial repeat ruleset.

    Anything that writes queue.mainPool.repeatRules must write the server's repeat ruleset instead. That covers scripts that edit settings, settings YAML kept outside SLM, and plugins that read the rules from a server's settings.

  • Added: Plugins can read, create, replace and delete repeat rulesets through slm/systems/repeat-ruleset, and choose which repeat ruleset their server applies. A plugin cannot delete a repeat ruleset that a server or rotation still uses. The audit log records every repeat ruleset change a plugin makes against the plugin.

  • Added: Plugins can search, read, create, clone, update and delete rotations through slm/systems/rotation, and add a rotation to their server's queue the way Add Rotation does. A search returns one page of rotations at a time, without their layers. A plugin's settings can include a rotation tag picker, and a plugin can create layer and rotation tags. When a plugin adds a rotation to the queue, it can clear chosen queue items in the same edit.

    A rotation a plugin creates is owned by the plugin, and the Rotations page names the plugin as its owner. Admins with rotations:write-all can still edit and delete it. A plugin can make an admin the owner instead. The audit log records every rotation change a plugin makes against the plugin. A plugin cannot replace a rotation's layers while an admin has unsaved edits to them open.

  • Added: Plugins can run jobs on a schedule, or once at a time they pick. SLM keeps scheduled runs across restarts, catches up a run that came due while it was down, and retries a run that fails. A run that cannot go ahead yet waits instead of failing, such as one that adds layers while an admin has unsaved queue edits, or one whose server is not loaded.

    The settings page lists each running plugin's jobs, with when each next runs, what a waiting run is waiting for, and how its last run went, and the runs it has scheduled. Use Run now to run a job straight away, Cancel to remove a scheduled run, and Stop to stop a running one. All three need the permission to manage plugins.

    The audit log records a job run that fails, including one still waiting when its time runs out or one that ran too long, a run an admin started by hand or stopped, and every run of a job that asks for its successes to be recorded. A job that runs for a server also appears in that server's activity feed.

    The plugin API adds slm/plugin/schedule.

  • Added: New permissions control rotations: rotations:create and rotations:write-all.

    The upgrade grants rotations:create to every role holding filters:create, and rotations:write-all to every role holding filters:write-all. Whoever created a rotation can edit it, along with the users and roles added to it as contributors.

  • Changed: The upgrade rewrites stored player death and wound events. It takes a few seconds per million events. An earlier version cannot read the rewritten events, so a downgrade drops them from the activity feed and history.

    Plugin PLAYER_DIED and PLAYER_WOUNDED events name the caused by actor damageSource instead of weapon. PLAYER_DIED also records deathVariant, which is killed or diedOfWounds.

  • Changed: The first start after upgrading takes longer than usual. SLM reads every recorded match once to collect the usernames players have gone by, so the time grows with the size of your match history.

  • Removed: SLM no longer ships the Balance Triggers plugin. Balance trigger alerts stop appearing on the dashboard, in match history and in post-roll warns.

    An upgrade keeps the plugin's settings and recorded trigger events where any were recorded. The Plugins section of the settings page lists them as leftover data, and an admin can delete them there. Where no event was ever recorded, the upgrade deletes the plugin's settings.

  • Removed: The global Top Bar Color setting is gone. The navigation bar's bottom border now follows the selected server's color, and the favicon is the plain SLM mark on every instance.

    The upgrade deletes topBarColor from the global settings, along with any comment on it and any role grant that names it.

  • Fixed: SLM no longer stops managing a server after its RCON connection drops mid-response.

    When an RCON connection dropped partway through a response, SLM could misread the first response after reconnecting and stop managing the server. The server's pages then failed to load until the server was disabled and enabled again, or SLM was restarted. SLM now discards the partial response. If SLM does stop managing a server after repeated connection failures, SLM starts managing it again after 30 seconds.

    A server agent that stops answering is dropped within 30 seconds, so the agent can reconnect straight away. Before, SLM held the dead connection for several minutes and refused each reconnect as a duplicate agent.

Smaller fixes and tweaks

  • Added: The plugin API is version 0.16. Plugins can read, add and remove the contributors of a filter or rotation, and copy one filter's or rotation's contributors to another. Plugins can read and change SLM's global settings and their server's settings.

  • Changed: An edit to a local admin list file takes effect as soon as the file is saved, instead of up to 30 seconds later.

  • Changed: The plugin API is version 0.18, because the settings type plugins read gained the tickets command. A plugin built for 0.17 does not load until its apiVersion is raised to ^0.18. Plugins also receive a TICKETS_CHANGED server event each time either team's tickets change.

  • Changed: The plugin API is version 0.17, because the settings type plugins read gained the squad-server:write-console permission. A plugin built for 0.16 does not load until its apiVersion is raised to ^0.17.

  • Fixed: A user who has left your Discord server is logged once, rather than with a warning each time SLM shows their name.

    Startup no longer logs Cannot read properties of undefined (reading 'guilds') errors, and SLM no longer asks Discord about the tutorial's stand-in admin.
